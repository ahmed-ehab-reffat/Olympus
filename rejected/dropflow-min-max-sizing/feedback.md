## Predicted traps (to compare against the batch)

1. Clamp applied after margin resolution (F-9): `max-width` + `margin: 0 auto` lands at x=0.
2. min-height and margin collapsing (F-3): sibling y offsets wrong, looks like a collapse bug.
3. Contributions not clamped (F-17): floats/inline-blocks around a constrained child come out at the child's unconstrained width.
4. Replaced ratio table (F-8): sequential clamp differs on the two "tighter axis" rows.
5. Percent min/max-height against an indefinite containing block (F-10 cell): resolving against 0 collapses boxes.
6. Percent limits inside intrinsic contributions (F-10 cell).

Defect found and fixed (reference bug, not a test bug):

- `layoutContribution` routed replaced boxes through `getConstrainedSize()`, which resolves PERCENTAGE min/max. meta.md states percentage limits are ignored in intrinsic contributions. Probe: `<div style="float:left"><img style="max-width:50%"></div>` gave float width 0 and img 0x0 (the percent resolved against an indefinite size). Correct/browser behavior is float 200, img 100x50.
- Fix: `getConstrainedSize(intrinsic)` resolves its four limits through new percentage-ignoring getters (`getIntrinsicMin/MaxInlineSize`, `getIntrinsicMin/MaxBlockSize`) when called from `layoutContribution`; `clampIntrinsicInlineSize` now derives from the same getters. Also removed a redundant nested block left in `layoutContribution`.
- No meta.md change: the existing sentence ("the intrinsic width contribution each box makes ... where percentage limits are ignored") already covers replaced boxes, so the solver-visible surface stays frozen and later test-only rounds remain Re-eval eligible.
- 3 tests added for the cross-product cell (replaced x percent limit x contribution): `image_percent_max_width_is_ignored_by_the_float_contribution`, `image_percent_min_width_...`, `image_percent_min_height_...`. Suite is now 92 tests.

Harness hardening (test.sh only):

- mocha's default 2000ms hook timeout tripped the repo's font-loading `before all` hook when the box was under CPU load (base run took 4s under a concurrent Docker build and failed; 5/5 clean at ~1s idle). Both modes now pass `--timeout 60000` so platform CPU contention cannot produce a false base failure.
- mocha's xunit reporter writes `failures="0" errors="N"` on a failing run. test.sh now rewrites the testsuite attributes so `failures` reflects the real `<failure>` count, in case the grader reads the attribute rather than the elements.

LOC after the fix (hand-written only, generated parser excluded): human-effective 234 -> 257 across 4 files. With the generated `parse-css.js` included the hook reports 1230.
