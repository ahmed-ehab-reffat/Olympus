revision, followed by the same pristine image preflight against that exact

The lock uses the untouched upstream `package.json` and adds only:

- `tsx@4.20.3`, used by `npm test` and `test.sh`; and
- `copyfiles@2.4.1`, used by the upstream `build-post` scripts.

The lock contains the complete resolved graph and is consumed by `npm ci` during
image build. Nothing is fetched when the container runs. The platform builds the
Dockerfile with the pristine upstream checkout as its context, so task-side
files are not available to `COPY`. For that reason, the Dockerfile contains a
plain JSON mirror of the canonical lock. The mirror is human-readable, contains
no encoded or compressed payload, and is byte-checked by the environment audit.
It is divided at existing line boundaries among bounded Docker instructions.
This matters because BuildKit may serialize a complete instruction onto one
progress-output line, while the platform reads build output with a 64 KiB
subprocess line limit. A single lock-sized instruction can therefore abort the
build-log reader before the agent starts. Every generated instruction remains
below 13 KiB. Run `node verify/sync-docker-lock.mjs` after changing the canonical
lock.

## Base runtime and cleanup compatibility

The Dockerfile uses the Node and npm toolchain already supplied by the required
`olympus-base-typescript` image. It does not download or install a second
runtime. This removes the only direct remote-file fetch from the image build.

The current base runtime changes Linux behavior for forced recursive removal of
an absent path with a trailing slash. The task runner contains a narrow base-mode
compatibility guard for the six upstream scratch paths affected by that change;
it does not alter production behavior or the focused enhancement suite. The
clean upstream suite passes 869/869 through the required task entry point.

Registry packages are installed exclusively with `npm ci` from the mirrored
canonical lock.
Every locked package has a fixed version, registry location, and integrity hash.
The resulting image therefore needs no package resolution or network access at
runtime.
