# FALSE-POSITIVE + REGRESSION LESSONS

Use this file after every rollout, adjudication, or review that finds a blocking false positive, passing-but-wrong implementation, base/test mismatch, fairness failure, environment-quality failure, verifier failure, or repeated regression pattern. Add the concrete failure and the prevention rule. Do not use this file as the home for healthy agent-fault misses from an otherwise good rollout; promote those reusable good patterns to `PLAYBOOK.md` and `lessons-learned.md`. Before finalizing any Olympus task, skim this file and ask whether the current hidden suite has the same kind of hole.

## Operating Definition

A task-level false positive is an agent submission that passes the verifier while failing at least one intended task requirement. If `meta.md` requires A, B, and C but the tests prove only A and B, an implementation that omits C can receive an invalid pass. That is a broken grading contract: either add a test that would fail when C is missing, or remove/clarify C if it was not actually intended. Do not preserve ungraded requirements in the prompt.

Treat the task as an exam and the tests as its grading rubric. A difficult exam is useful only when a passing result reliably means the student met the stated goals. Before any agent run, complete a bidirectional requirement-to-test matrix: every intended prompt clause maps to a named behavioral assertion, and every non-inferable assertion maps back to prompt text or a direct repository convention. A row is covered only when a plausible implementation that omits or misimplements that clause fails the named assertion.

The platform's Test Fairness check exposes pre-run suggestions behind the 💡 icon. Review every suggestion before starting agent runs or the slower FP panel, and classify it as:

- a real coverage gap: add a public-behavior test and rerun the affected local verifier gates;
- a prompt/test scope mismatch: add coverage if the requirement is intended, or remove/clarify the prompt clause if it is not;
- noise: keep the artifacts unchanged and record a concrete dismissal reason in `feedback.md`.

The suggestions are leads, not a completeness certificate. An empty 💡 panel never replaces the bidirectional matrix and omission audit. Do not launch agents with a plausible coverage gap unresolved. After any agent passes, audit its patch against the complete requirement matrix rather than trusting the green score alone. If it missed a requirement, treat the run as a confirmed false positive, add the exact deterministic regression, realign the prompt if needed, and rerun fairness/verifier checks before spending more agent runs.

## Mandatory Five-Sweep Final Alignment Gate

Every task requires **five separate alignment sweeps at the end**, after the last intended `meta.md` or `test.patch` edit. Record each result in `feedback.md`; a sweep either adds/strengthens a named behavioral test or records a concrete no-gap reason.

1. **Clause-omission sweep:** atomize every normative `meta.md` clause and apply the counterfactual: if an agent implemented every other row but omitted this one, which named public assertion fails for this requirement's reason? Delete unintended prose or add coverage wherever the answer is unclear.
2. **Test-gap sweep:** walk every public API and lifecycle independently: adapters, modes, input forms, positive/error/recovery paths, repeated/nested/cyclic state, reset and read-only behavior, persistence/read-back, preservation, summaries, and renderers. Use solution branches, checker suggestions, and passing or near-passing patches only as gap leads. Add a named public consequence for every intended gap; do not invent a requirement to increase test count.
3. **Test-mismatch/fair-alternative sweep:** list every assertion that selects an exception type, rejection layer, sentinel, wrapper/container shape, label, punctuation, placement, casing, ordering, raw-versus-decoded representation, option behavior, or rollback boundary. For each choice, cite prompt text or a direct public repo contract and run a reasonable-alternative mutation/probe when plausible. If a contract-compliant alternative fails, normalize or soften the test. Do not expose implementation HOW merely to rescue the reference solution. Sweep every sibling assertion with the same assumption.
4. **Passing-but-wrong sweep:** inspect every passing agent patch row by row. Also propose at least three fresh, realistic public-behavior probes against plausible shortcut implementations. Any green patch that misses a row is a confirmed FP and must gain an exact deterministic regression before more runs.
5. **Verifier/base-mode sweep:** rerun new-on-base, base-before-solution, new-after-solution, and base-after-solution; inspect JUnit nodes/counts for zero passing new tests on base, disjoint base/new nodes, no stale or duplicate names, parseable failure XML, and no hidden environment/build contract absent from `meta.md`.

Run all five once the first complete meta/test pair exists. Repeat all five after every successful or near-passing rollout, every reviewer/checker finding, and every prompt/test change. Before changing artifacts for a failed assertion, classify it as a stated public miss, a reasonable contract-compliant alternative, or an uncovered intended consequence. A Test Fairness 💡 pass does not replace any sweep.

## Global Rules

1. A hidden new test should not pass on the base commit. If a regression guard only checks pre-existing behavior, compose it with the new feature or move it to base-suite validation. The platform can mark a base-passing hidden test stale even when the assertion is useful.
2. Do not rename, delete, or rewrite existing baseline test nodes in `solution.patch`. If an old test expectation becomes obsolete, preserve the test name when possible and update the behavior only when the repo's visible suite itself needs that change. Prefer adding new hidden coverage over editing old tests.
3. Run the complete pre-existing base suite unless a specific broken package is documented. Subsets miss unrelated regressions in touched files and in sibling CLI/API paths.
4. Every stated behavior in `meta.md` needs a hidden assertion. This includes flat behavior, lifecycle behavior, alternate reader/writer paths, plural commands, invalid/rejected cases, and deep composition. Dense compositional tests are good, but they are not permission to leave a stated clause untested.
5. If a behavior is repo-inferable and used as a regression guard, test it through the new feature path so it fails on base for the right reason. Do not make an existing-behavior-only hidden test.
6. When a feature touches a dispatcher, CLI, plugin registry, enum, or conversion layer, test both the leaf helper and the real entry point. Agents often implement the helper and forget the call site.
7. When a feature touches file or stream state, test multi-step lifecycles: partial read then read, chunked reads, lazy materialization after close, non-seekable streams, save/reopen, and rewritten output. Single-shot happy paths are not enough.
8. Error-message requirements must be scoped exactly. Require stable words only for the specific error path that needs them; do not accidentally require every invalid input to mention the same diagnostic.
9. After adding a regression guard, run base-only new mode and inspect the JUnit/XML counts. The target is zero passed new tests on base unless the harness intentionally skips unsupported environment cases.
10. If a solution passes hidden tests but a reviewer finds a real false positive, add a deterministic hidden test for that exact behavior before the next rollout.
11. Before submitting, build a meta-to-test matrix. Every clause in `meta.md` must name at least one assertion, even if the clause is flat, obvious-looking, a build target, an error path, a summary count, a deep composition, or a preservation rule. Do not rely on "compositional enough" as a reason to skip direct coverage.
12. If a hidden test manipulates environment state, build metadata, filesystem trust, or CLI wrapper behavior, `meta.md` must state that contract explicitly. Repo-obvious preservation is fair; hostile or degraded environment behavior is not fair unless stated.
13. After hidden test add/remove/rename, verify active test names against JUnit output and fallback XML. Stale removed testcase nodes, duplicate node IDs, or old hashed namespaces are blocking verifier bugs; rotate the namespace or regenerate the runner lists before rollout.
14. Docker can satisfy raw Environment Quality, but it must not mask task tests. If a final-container env skip is used for one known upstream raw-command failure, document the exact test/package and reset the env inside `test.sh` so base/new JUnit suites still exercise the intended code.
15. Private setup is allowed only to create rare states. The assertion must go through a public API, persistence/read-back, CLI/report protocol, or normal runtime path. A private setup plus private assertion is a fairness failure unless `meta.md` explicitly makes that private state public contract.
16. Determinism beats scope. If a proposed test needs wall-clock time, random data, external services, or private-only state to compute the expected value, add a public reference input/oracle or remove the behavior.

## Cross-task strategy-mutant portfolio, 2026-07

The Canvas, Molstar, Cosmic Text, go-mail, str0m, Cantools, Fluent, gqlparser, excelize, pynetdicom, and gopher-lua cycles exposed the same verifier weakness in different domains: large suites can still use correlated fixtures that never distinguish the intended strategy from a plausible shortcut. Before rollout, choose at least three of these public probes across two cooperating subsystems:

- **Make authorities disagree.** Preferred and fallback sources, inner and outer metadata, explicit and inferred state, or stored and recomputed values must disagree in a final lifecycle. Agreement proves neither precedence nor ownership.
- **Isolate each criterion.** If a filter or validator promises A, B, and C, create valid public cases where only A, only B, and only C decides the outcome. A fixture satisfying all three cannot prove any one clause.
- **Cross role and vocabulary boundaries.** Feed foreign-role field names, sibling-version names, unsupported-but-valid media, or recipient-like names into report-level blocks. Assert positional/structural ownership rather than content-sniffing heuristics.
- **Cross representation stages.** Separate raw, transfer-decoded, syntax-decoded, typed, validated, and persisted states. Test empty-after-decode, literal escape characters, wrong-codec syntax under a typed mode, and malformed input that preserves siblings.
- **Treat user values as hostile format data.** Probe every sibling command or formatter parameter with `%`, braces, backslashes, separators, and the repository's format metacharacters. A fix for one parameter does not prove the adjacent one.
- **Use a state-presence matrix.** Distinguish absent, present-empty, whitespace-only, malformed, and valid values whenever the public contract treats them differently. Do not assume a literal-empty test covers encoded-empty or an absent field covers an empty field.
- **Audit shared semantic blast radius.** When changing a matcher, filter, traversal, dispatcher, normalizer, or serializer, add a feature-positive test and one unrelated existing-consumer regression. Canvas showed that a local current-color fix could break URL paint and marker inheritance.
- **Use an independent oracle.** A comparison against the reference must include a separate feature-positive anchor that fails on base; two implementations sharing the same omission do not certify behavior.
- **Invoke adapters at runtime.** Compile/import checks do not prove plugin, CLI, loader, renderer, or transport integration. Exercise the public adapter and at least one three-hop lifecycle from input through the semantic core to read-back/output.
- **Split replacement and absence paths.** Replacement filtering and append-when-source-absent, surviving-relationship closure and node inventory, or configured and legacy fallback are different loops and require different witnesses.

Passing patches remain provisional until their actual source is available for row-by-row audit and at least three fresh probes. Evaluator summaries alone cannot certify a patch. Collapse JUnit parent/subtest failures into unique semantic causes when judging difficulty; repeated near-passes at the same cause indicate a specification or architecture SPOF, not healthy breadth.

The concrete evidence behind this portfolio must remain recognizable:

## Cross-problem verifier and fairness blockers, 2026-07

- **Stale JUnit nodes after hidden-test edits.** Expr carried synthetic failures for removed `TestVars_*` cases after the active public variable-list API was intentionally removed. Why it happened: the source suite changed but the wrapper-facing testcase namespace/fallback surface still referenced old names. Prevention: after any add/remove/rename, compare source tests, runner filters, fallback XML, and solution/new JUnit; rotate the hidden hash when a large rename could leave stale expectations. Local validation: `rg '^(func Test|#\[test\]|def test_)'` in the applied test files and compare with parsed JUnit testcase names.
- **Raw Environment Quality ignored `test.sh`.** Expr and DHCPv6 showed that platform environment checks can run raw `go build ./...` / `go test ./...` before patches or without the task runner. Why it happened: Docker only proved `test.sh`, while the raw repo command had an upstream fixture or sandbox-sensitive test. Prevention: make the Docker image satisfy likely raw commands, or use an exact documented raw-only env skip and reset it in `test.sh`. Local validation: run the raw commands offline/non-root in the final image as well as base/new JUnit.
- **New mode accidentally included old tests.** Build tags and suffixes do not by themselves guarantee that only new tests run. Why it happened: broad runner filters executed baseline nodes in new mode, creating P2P/F2P overlap. Prevention: new mode must filter to the new test names and base/new JUnit node sets must be disjoint. Local validation: extract testcase `classname/name` pairs from both XML files and require no overlap.
- **Private or unguessable public surface.** FontTools and DHCPv6 reviews rejected hidden tests that imported internal submodules, called private helpers, or asserted pointer identity/private state. Prevention: if tests need a type, method, field, or row shape, import it from the documented public surface and name it in `meta.md`; otherwise assert behavior through public outputs. Local validation: grep hidden tests for internal package paths, unexported helpers, pointer identity, and direct private field/cache assertions.
- **Formatter/output grammar under-described.** Expr, FontTools, go-containerregistry, and Fluent iterations all hit exact-format fairness warnings. Why it happened: tests compared line layout, labels, delimiters, row order, issue detail, or tuple/empty representation without an equivalent prompt contract. Prevention: either state the exact public grammar and test it, or parse/normalize only the semantic fields the prompt owns. Local validation: grep tests for whole-output equality, fixed indexes, exact empty containers, and literal labels; map each to one prompt sentence.
- **New repository-level nextest config rejected by the selected-commit path validator.** A Rust task added `.config/nextest.toml`; the platform rejected the upload with "Patch changes files that do not exist in the selected repo" even though new `test.sh` and hashed test files were accepted runner artifacts. Prevention: keep Rust `test.patch` additions to the standard runner and test files when the upstream lacks a nextest config. Have `test.sh` create a task-scoped temporary config, pass it through `cargo nextest run --config-file`, direct native JUnit to `--output_path`, and retain a parseable setup-failure fallback. Local validation: grep patch headers to ensure no extra repository-level config path remains, then repeat all four clean verifier gates and XML-node checks.
- **Free-form rejection diagnostics pinned without a prompt contract.** The str0m simulcast-alternatives suite correctly required invalid SDP offers and reoffers to reject and preserve state, but four assertions additionally required `RtcError::RemoteSdp(String)` display text to contain `rid`. The prompt did not specify diagnostic wording and the repository deliberately exposes a free-form string, so Test Fairness rejected those checks. Prevention: when the product contract is rejection plus rollback, assert the error result and every public state/output consequence; match diagnostic words only when the prompt or an established typed error contract owns them. Do not expand `meta.md` merely to rescue a brittle hidden assertion.
- **SDP allocation proof did not substitute for live RTX parity.** The same review identified that counting FID pairs in generated SDP did not prove comma alternatives shared repair state during packet loss. It also identified that a duplicate across semicolon groups did not prove duplicate detection inside one comma group. Prevention: for grouped protocol state, cross the syntax partition both ways and exercise the live control path: same-group and cross-group malformed inputs, loss/NACK/retransmission on more than one alternative, repair-SSRC equality within a group, repair-SSRC inequality across groups, cumulative public stats, and reoffer read-back. Keep these observations public through SDP, packet events, and stats rather than private stream maps.
- **Malformed known attributes fell through as ignorable unknowns.** In str0m, malformed `a=simulcast` separator forms can fail the typed attribute parser and become an unused attribute, which lets a semantic consistency check disappear unless the accept lifecycle recognizes the exact known attribute. Prevention: enumerate each prompt-owned malformed form (empty comma alternative, empty semicolon group, and trailing comma/semicolon), test offers and answers plus initial/active rollback, and include a malformed second direction. Pair that with a valid unknown near-name such as `a=simulcast-extra` so the fix cannot reject every unused attribute or every prefix match.
- **The conditional no-RTX inverse was only implied by RTX tests.** Live RTX sharing does not prove behavior when the configured video payload has no RTX; an implementation can allocate repair SSRCs unconditionally for video and still pass every RTX-positive scenario. Prevention: state the configuration boundary, then assert generated offer and answer SSRC/FID cardinality and live same-group/different-group main-stream behavior. Do not silently widen this into offered-but-declined RTX policy unless the prompt owns that separate negotiation mode.
- **Verifier build selection leaked into the product prompt.** The str0m draft described the root Linux/default-crypto test target even though the public feature did not expose a build-mode choice. Prevention: keep normal root-package, offline, and non-root build checks in `test.sh`, Docker proof, and `feedback.md`; put a build contract in `meta.md` only when the solver must implement product behavior that changes by target or feature. Removing harness noise also removes the need for a synthetic hidden build assertion.
- **Atomicity was stated twice, once as implementation order.** The str0m draft said to validate the complete SDP before mutation and later stated the stronger observable contract that every rejected offer, answer, or reoffer leaves media, streams, statistics, and output unchanged. Prevention: keep the complete public rollback outcome and remove validate-before-mutate wording when tests cannot and should not distinguish validation-first from a correct transaction/rollback implementation. Likewise, do not repeat obvious backward compatibility in `meta.md`; retain its compositional regression under direct repository basis and label that basis in the matrix.

## mp4ff sample timeline, 2026-07

This task exposed a full cycle of blocking false positives, base/test mismatches, fairness failures, verifier failures, and reviewer regressions. The final healthy Go CLI/reporting pattern is promoted in `PLAYBOOK.md` and `lessons-learned.md`; this section keeps only the avoid/regression checklist from the earlier blocking issues.

### Harness and verifier failures

- **Missing `test.sh`.** The verifier failed before tests with `./test.sh: No such file or directory`. Prevention: every `test.patch` must add executable `test.sh` (`new file mode 100755`) and local validation must apply `test.patch` to a clean base and run it.
- **Overbuilt custom JUnit converter.** A custom Python XML fallback attributed base tests to one package and could collapse package failures. Prevention: use the repo/language native reporter when available, such as `go test -v | go-junit-report`, and verify real `<testcase>` counts.
- **Base-passing new test.** A Makefile regression guard originally passed on base, so Verify Solution rejected it as stale. Prevention: every new-mode test must fail, error, or skip on base. If testing preservation of old behavior, compose it with the new feature or move it to base-mode validation.
- **Weak Makefile dry run.** `make -n` caught the old single-file build command but not real build/VCS failures. Prevention: run the actual target and assert the produced binary exercises the new feature.
- **Prompt/test mismatch for degraded Git metadata.** Requiring `make mp4ff-info` to pass with broken `GIT_DIR` was unfair until `meta.md` said the target must work without Git metadata. Prevention: if tests break Git metadata, source snapshots, trust config, env vars, or caches, state the degraded-environment contract.

### Go CLI/build lessons

- **Sibling command files broke `make mp4ff-info`.** The old Makefile built `./cmd/mp4ff-info/main.go`, so moving implementation into sibling command files made hidden Go tests pass while the repo build target failed. Prevention: for Go command targets, build the package (`./cmd/$@`), not one file, and add a real Makefile target regression when the CLI is part of the task.
- **VCS stamping failed in harness.** `go build` can fail with VCS status errors or missing trusted Git metadata. Prevention: use `-buildvcs=false`, make Git version/date fallbacks explicit, create output directories, and validate with bad `GIT_DIR` only when `meta.md` says no Git metadata is required.
- **Go Dockerfile shape matters.** Approved Go shape is build-time `go mod vendor`, `GOFLAGS="-mod=vendor -buildvcs=false" go build ./...`, installed `go-junit-report`, writable Go caches, and non-root runtime validation. Do not rely on runtime network or missing reporter tools.

### mp4 timeline behavioral misses

- **File-scope sidx actual size with segment sidx boxes.** Hidden helpers originally undercounted or matched candidate bugs. Prevention: test file-scope `actual_size` on encoded segments that include segment-level `sidx` boxes.
- **Segment-scope later-reference range size.** Agents counted only fragment 2's `moof`/payload and missed bytes before that `moof` that belong to reference 2. Prevention: specify and test that segment-scope `actual_size` is the declared reference byte range from the sidx anchor plus `first_offset` plus prior reference sizes.
- **Cumulative declared earliest for later refs.** Agents reused the box-level earliest time for reference 2. Prevention: test valid multi-reference sidx rows where ref N declared earliest includes preceding reference durations.
- **Hierarchical sidx without fragments.** Agents checked fragment availability before hierarchical reference type and reported `sidx_without_fragments`. Prevention: test ReferenceType=1 both with and without corresponding media fragments; hierarchical reference wins and emits a problem, not a row.
- **Invalid explicit `trun.data_offset` leaked cursor.** After a valid run, an out-of-range explicit offset, then a no-offset run, agents reused the previous cursor. Prevention: test invalid explicit offsets followed by no-offset runs; samples after the invalid offset must have unknown offsets.
- **Unsupported edit overlap.** Agents returned `unsupported` when any unsupported edit covered the PTS, even if a later supported edit also covered it. Prevention: test overlapping supported/unsupported edits; supported mapped coverage wins unless the sample is covered only by unsupported rates.
- **Encoded media rate for unsupported edits.** Agents ignored the edit entry rate when deciding unsupported coverage. Prevention: test rate-adjusted unsupported edit coverage and one `unsupported_edit_rate` problem per edit-list entry, including empty edits with `MediaTime=-1`.
- **No-edit movie time.** Agents emitted `movie_time=-` when no edit list existed. Prevention: specify and test that no-edit samples still map PTS into movie timescale with `edit=-`.
- **Mixed progressive/fragmented tracks.** Agents dropped progressive sample-table rows when other tracks were fragmented. Prevention: test files where sample-table and fragmented tracks coexist; source reflects emitted samples, not merely `mvex` presence.
- **Global/progressive ordering.** Agents often get multi-track sample ordering wrong. Prevention: test progressive rows track-by-track in track-row order and fragmented rows by segment, fragment, traf, trun.
- **Contradictory prompt wording.** "Order irrelevant" conflicted with precise ordering tests. Prevention: remove broad softening phrases when later clauses require order.
- **Public API overreach.** A solution exported `mp4.File.WriteSampleTimeline` though the task only required the CLI. Prevention: keep reporter implementation private under the command package unless `meta.md` specifies a library API and tests it.
- **Documentation and formatting.** Reviewers caught missing `cmd/mp4ff-info/doc.go` option text and `gofmt` failures. Prevention: update existing help/doc surfaces and run `gofmt -l` on every new Go file.

## gortsplib RTP-Info resync, 2026-07

This task exposed environment-quality and blast-radius lessons for Go networking repos.

- **Runtime-wide Docker `GOFLAGS -skip` is too broad.** A Dockerfile-level `-skip=^Test(ClientPlay|ServerPlay)` hid whole PLAY families from every `go test` in the container. Prevention: keep Docker `GOFLAGS` to build/vendor/VCS flags; put unavoidable environment exclusions in `test.sh` base mode only, with a comment naming the offline-broken cases.
- **Run touched packages fully.** Base mode originally ran only a few functions while the solution changed several packages. Prevention: run all tests in touched support packages and a broad root-package pass; skip only named offline-broken multicast cases.
- **Multicast/network helpers are environment-sensitive.** Some unicast-looking subtests call multicast-capable IP helpers. Prevention: audit test source before choosing skips; document whether a skip is truly multicast-only or helper-dependent.
- **Handler-provided RTP-Info preservation needed repeated PLAY coverage.** A first-PLAY test did not catch regenerated headers on repeated PLAY. Prevention: every state/lifecycle promise needs a repeated or already-active case when the code has separate first/repeated paths.
- **Multi-format media rejection was undercovered.** Testing rejection only when both `seq` and `rtptime` were present missed single-origin ambiguity. Prevention: for ambiguous-origin rules, test each origin independently and together.
- **Partial setup was undercovered.** No test used an RTP-Info entry for a described but unset-up media. Prevention: when meta says entries match setup media, add a partial-setup case.
- **Pending/resync counters needed precise lifecycle assertions.** Clearing pending on any packet or zeroing lost counters could pass weak tests. Prevention: assert pending before a dropped older packet and after first accepted packet; assert nonzero lost counters survive resync.
- **Solution public API bloat was flagged.** Several exported RTPInfo helpers had no tests/callers. Prevention: delete unused public helpers; keep only public API specified in `meta.md` and exercised by tests.
- **Count real receivers, not formats.** Rejecting `len(cm.formats) != 1` ignored nil-receiver filtering. Prevention: test wording that says "formats that have a receiver" with nil/non-nil combinations.

### Final false-positive and verifier hardening

- **Passing-but-wrong `GlobalDecoder.SetOrigin`.** A candidate passed all hidden tests while recording an RTP origin immediately changed global leading-track timing. A different track that decoded first then started at a nonzero PTS. Why it happened: tests covered two tracks with origins and one no-PTS single-track case, but not one origin track plus a no-origin track decoding first. Prevention: when meta says recorded state takes effect only after a later decodable event, add a mixed-object case where another object/event proceeds first. Local validation: `TestGlobalDecoderOriginDoesNotLeadOtherTracks...` or equivalent must fail on the bad candidate and pass the reference.
- **Passing-but-wrong authenticated absolute URL matching.** A candidate passed hidden tests but compared absolute RTP-Info URLs with credentials included. Authenticated clients keep credentials in their base/media URL, while server RTP-Info absolute URLs normally omit them, so PLAY failed with `ErrClientRTPInfoInvalid`. Why it happened: all URL tests used credential-less URLs. Prevention: any URL identity rule should include a credential-stripped comparison case when the repo already strips credentials on outbound requests. Local validation: run an authenticated client against a server returning a normal absolute media URL and assert PLAY succeeds through the public path.
- **Contrived URL heuristic probes can be unfair.** A proposed probe used a root-relative path containing `://` inside the path to catch `strings.Contains(raw, "://")`. It discriminated from the reference but described no realistic RTSP control URL and was not required by the prompt. Prevention: add realism and prompt-support checks before promoting a probe from adjudication into hidden tests. Local validation: reject probes that only fail an implementation heuristic on unnatural input unless `meta.md` explicitly states that parser contract.
- **Late discriminator edits can stale Verify Solution.** After adding new hidden cases, `./test.sh new` may fail even if the old solution was green: `NEW_CASES` can be incomplete, hunk counts can be stale, or the reference solution can miss the new behavior. Prevention: every test edit reruns the exact clean-checkout order `test.patch` then `solution.patch`. Local validation: inspect the generated XML and require `failures="0"`, `errors="0"`, and `skipped="0"` after solution.
- **Near-cap meta word counts are fragile.** A late hint pushed the description to a platform-reported 501 words even though a local count appeared lower or was run on a stale file. Prevention: leave margin after late hints; target about 480 words, not 498-499. Local validation: run `python -c 'print(len(open("meta.md").read().split()))'` on the exact submission file after every meta edit.

## DHCPv6 relay path, 2026-07

The final 2/14 rollout was fair and no confirmed task-level false positive remained. This section records the review-time FP risks, coverage holes, and harness regressions that were closed before approval. The healthy rollout misses and their rates live in `PLAYBOOK.md` Pattern 44.

### Prompt/test alignment and over-constraint fixes

- **Compile-facing public metadata shape was under-described.** Three early runs used `RelayHop.RemoteID []byte`, and another omitted or renamed `ClientLinkLayerType`, causing package-wide compilation failure before semantic tests ran. Why it happened: hidden tests constructed/read the exported model while the prompt initially described only generic copied metadata. Prevention: if compiled tests construct, assign, or dereference an exported field, state the non-obvious repo-native shape, such as reusing an existing option type; otherwise normalize through a stable public behavior rather than choosing a wrapper for the candidate. Local validation: grep tests for composite literals, field assignments, dereferences, and concrete callback signatures on new public types.
- **Malformed-hop survivorship was initially ambiguous.** Near-passes disagreed about whether a missing-payload terminal relay with no metadata, header metadata, or an invalid payload remains in `Hops`. Prevention: define survivor categories behaviorally: truly empty terminal wrappers may be issue-only, metadata-bearing or invalid-payload wrappers survive, and malformed chains do or do not expose a final inner value as stated. ### Wording lessons from laspy

- "Rejected CLI storage requests exit nonzero" is fair. "All rejected CLI storage requests mention internal waveform storage" is too broad; only internal-storage-on-LAZ needs that diagnostic.
- "Add `--waveform-storage` to compress/decompress/convert" is enough. "Only these commands..." can over-constrain parser plumbing unless tests actually forbid shared options elsewhere.
- Do not spell "use a separate handle/BytesIO" in meta. The public behavior is that lazy/eager internal reads work across normal reader lifecycles without corrupting point reads.
- Do not spell internal call sequences such as `seek([0, 2])`. Assert public materialized samples and point records.
- A mixed-directory `convert` test that required atomic cleanup after one rejected input was removed because the prompt owned nonzero rejection, not all-or-nothing output semantics.

## Rejection-phase ownership mismatch, 2026-07

- **A rejection contract does not choose the rejecting layer.** The str0m RID-alternatives suite required semantically invalid SDP to succeed in `SdpOffer::from_sdp_string` or `SdpAnswer::from_sdp_string` and fail only later in `accept_offer` or `accept_answer`. Nova implemented the complete behavior but reasonably placed consistency validation in generic SDP construction, producing an unfair 44/50 Test Mismatch.
- **Test the public consequence across every reasonable rejection boundary.** For invalid external input, attempt construction first. If construction rejects, accept that result; if construction succeeds, require the consuming API to reject. After either outcome, assert the stated atomic media, stream, statistics, persistence, or output consequences. Pin a phase only when `meta.md` or an established repository contract explicitly owns that phase.
- **Keep positive controls phase-specific.** Valid inputs, serialization, reparsing, read-back, and successful application must still succeed at each required public boundary. This prevents flexible negative tests from rewarding an implementation that rejects supported input indiscriminately.
- **Sweep all sibling invalid paths after one phase mismatch.** The reported six str0m failures contained nine individual offer/answer parser pins. Fixing only the displayed panic sites would leave the same unstated assumption in adjacent duplicate, undefined, wrong-direction, malformed, late-section, or reoffer paths.
