### Gate 1 — BEHAVIOURAL F2P GAP, REPRODUCED ON BASE (two independent failures)

Driver: a plain `Schema` subclass, public API only, no reflection.

```
--- probe 1: schema with zero recursive types ---
  java.util.NoSuchElementException: No value present
--- probe 2: mutual recursion a<->b declared non-recursive ---
  java.lang.StackOverflowError
```

- **probe 1** is `Schema.buildTypes()` doing `templates.stream().reduce(DSL::or).get()` over the
  recursive-types map. A schema that registers no recursive type cannot be constructed at all.
  Open issue [#45](https://github.com/Mojang/DataFixerUpper/issues/45) "Type Building Assumes that
  you have recursive types", filed 2020-02-14, **0 comments, still open**.
- **probe 2** is the load-bearing consequence of `Schema.java:144`'s own
  `// TODO: calculate recursiveness instead of hardcoding`. `Schema.id(name)` returns `DSL.id(recurseId)`
  when the caller declared the type recursive and **inlines the whole template otherwise**, so a type
  that is genuinely in a reference cycle but declared `recursive=false` inlines forever.

### Stage 3b — ABSORPTION TEST: PASSED, and mechanically

Name the algorithm the repo does not contain: **a reference graph over lazily-supplied type templates,
plus cycle detection over it, plus a deterministic recursion-id assignment.**

- `TypeTemplate` exposes exactly `size()`, `apply(family)`, `findFieldOrType`, `hmap`, `applyO` —
  **there is no way to ask a template which registered types it references.** No child enumeration,
  no visitor.
- `grep -rniE "tarjan|strongly|scc|cycle|visited|topolog|indegree" src/main/java` returns **zero**
  matches in the whole repo.
- The only cross-type reference mechanism is `Schema.id(name)`, which *resolves* eagerly and never
  records an edge.

So this is not a missing arm of a dispatch: the machinery to answer the question does not exist at
any level, and building it forces a two-phase schema construction that the constructor does not have.

### Trap structure (interdependent + misdirecting)

1. **Mutual recursion `a -> b -> a`.** A self-reference check clears probe 1 and dies here (F-5 transitive).
2. **`DSL.taggedChoiceLazy` sub-templates.** Edges hide behind `Supplier<TypeTemplate>` inside a map;
   a walker that does not force them under-detects, and the resulting StackOverflow surfaces far from
   the walker. Misdirecting.
3. **Id ORDER, not just the id SET.** `recursiveTypes` is an `Object2IntOpenHashMap`, and `buildTypes`
   reduces the per-type `DSL.check(...)` templates with `DSL::or` in that map's iteration order — the
   order IS the family's internal index layout. Right set + wrong order builds fine and decodes wrong.
   Silent.
4. **Declared-vs-derived conflict.** Minecraft declares types recursive that are not actually cyclic;
   a pure derivation that drops them changes existing types. Traps 1 and 4 pull in opposite directions,
   so a local fix to either regresses the other.
5. **Zero-recursive-types path** (probe 1) must stop crashing without a fake anchor.
6. **Parent-schema references** — `schema.id(name)` for a name registered only in the parent version.

### Phase-3 death-class guard

1. **One kernel, several surfaces:** the derived recursion set feeds `buildTypes` -> `RecursiveTypeFamily`
   -> every `Type` in the schema -> `getType` / `getChoiceType` / `findChoiceType` -> the DataFixer's
   rewrite rules. YES.
2. **Interdependent traps:** 1<->4 and 2<->3. YES.
3. **Solvable by a standalone new file + minimal wiring?** No — `Schema`'s constructor order
   (`registerTypes` then `buildTypes`) has to become two-phase and `TypeTemplate` needs a capability
   it does not have.
4. **TOO-EASY Guard #2 (single-subsystem fully-specified transform):** spans `schemas` + `types/templates`
   + `types/families` + `DSL`.

## Method notes worth keeping

1. **⭐ The proven pool still had one un-mined repo, and it was the best lead of the session.** The
   Stage 0-bis pool query returns repos, but the sessions since 09-01 have been triaging them
   REPO-by-REPO and marking a repo done once one lane died. DataFixerUpper had never been triaged at
   all — it was invisible because it is the only Java repo in the pool and every sweep since has been
   Rust/Python/C++-shaped. **Diff the pool against the ledger mechanically before every sweep**, and
   sort the un-mined ones to the front:
   ```bash
   for f in approved-problems/*/meta.md problems/*/meta.md; do grep -m1 -i '^Repository:' "$f"; done \
     | sed 's|.*github.com/||; s|/*$||' | sort -u \
     | while read r; do grep -qi "$r" Instructions/SATURATED-REPOS.md || echo "UN-MINED: $r"; done
   ```
2. **⭐ A repo with no `.github/workflows` is not automatically a Requirement-7 reject — look for
   another CI system in the tree.** `ls -a` at the repo root found `.ado/`, and `.ado/build.yml` runs
   `gradle build test publish` on every branch and PR. `gh run list` cannot see it. The cheap
   confirmation is to build and run the suite yourself, which the gate already owes you at Stage 3
   anyway: 52/52, 3x identical, in under a minute with plain `javac`.
3. **Stage 2b-bis is now the top killer, ahead of absorption.** Five of this session's seven
   mechanically-clean sweep survivors died to competitor profiling. Two recorded accounts
   (`ChrisJr404`, `binggao1230`) turned up on three unrelated repos each. Run the profiler BEFORE the
   seam audit, always.
4. **A rival author's PR titles are the tell, not the account age.** `u33549` on Fields2Cover writes
   titles in our own house style ("Report which cell gives each corridor, and let callers ask for a
   fair split"). Read the titles as a set: a stranger who files nine capability-shaped PRs in five
   weeks on one niche engine is mining it.
5. **A six-year-old zero-comment issue is not automatically the magnet reject.** The magnet rule's
   HIGH row needs an EXTERNALLY nameable capability. DFU #45 is an internal crash in a Minecraft
   library — nobody converges on it from a spec. Grade the CAPABILITY, not the issue's age.
6. **`pkill -f '<pattern>'` kills the shell running it** when the pattern appears in that shell's own
   command line (this is the 09-09-B self-matching lesson in its second form — it cost a lost heredoc
   and a confusing exit 144 today). Kill by PID, or match on something the caller cannot contain.
7. **`eda` is a poisoned topic** — it returns exploratory-data-analysis repos, not electronic design
   automation. Use `verilog` / `fpga` / `netlist` / `hdl` instead.
