## RANK 1 — tyfkda/xcc (C, MIT) ★549 — frame-reusing tail calls across three native backends

- **Mechanics:** MIT, pure C (gcc + make, 5 s build, outputs gitignored), `AllTests` CI green on main,
  `make test` 3x identical (1533 assertions, ~13 s). 231 commits/12mo, 228 by `tyfkda`; 0 open PRs;
  no signature accounts. Quota 0/6. Candidate base `a596d27e7ebc3c898181e240f5de9e08202e1b90` (v0.1.13).
- **Lane:** calls in tail position on x64 / aarch64 / riscv64 reuse the caller's frame, so tail- and
  mutually-recursive code runs in constant stack, identical behaviour elsewhere, in both the default
  and SSA pipelines. wcc (wasm) excluded: maintainer's `feature/jspi` branch is live there.
- **Missing algorithm:** xcc leaves a function only through `ret` (`IR_TJMP` is the switch table
  jump). Needed: tail-position recognition after `optimize()` for both IR shapes; an escape check in
  xcc's storage model (arrays/structs/compound literals escape via `IR_BOFS` without `VRF_REF`,
  `va_start` pointers into `vaarg_frame_info`, large by-value structs as caller temps on
  aarch64/riscv64); per-arch lowering with outgoing stack args staged into the caller's incoming slots
  (parallel-move hazard); riscv assembler/linker work (`tail` unsupported, external `j` gets the
  ±2 KiB `R_RISCV_RVC_JUMP`, `ld.c` relaxes `R_RISCV_CALL` into `jal ra`).
- **Size:** ~300 eff (260-340) across 9-11 files, 4 subsystems (backend, 3 emitters, as, ld).
- **F2P:** 10M-deep mutual recursion segfaults (exit 139) on all three targets (aarch64/riscv64 via
  xcc cross builds under qemu-user in `olympus-base-cpp`, same pin as the approved Cwerg image).
- **Shortcuts measured:** AST self-recursion-to-loop (60-100 LOC) fails mutual/indirect cells;
  per-arch "call; ret -> jmp" peephole (~100 LOC) miscompiles escape / va_list / struct-by-pointer /
  setjmp cells and fails stack-arg and riscv far-jump cells. Lane survives.
- **Exclusivity:** repo PRs, issues, 40 branches and 3037-commit history clean, no removal record;
  no tail-call implementation in chibicc, tinycc, cproc, slimcc, lacc, 8cc. No self-collision.
- **Death-class guard:** one shared kernel (tail-position + escape decision in the backend) feeds
  three emitters and the as/ld path; a local fix in one arch regresses the others' contract; the
  escape rule, stack-arg staging and riscv relocations interlock. Not a standalone post-pass.

### Risks
- **Derivative MEDIUM-HIGH:** "add tail-call optimization to a C compiler" is outsider-nameable and
  the README carries "* Optimization" under TODO. Phrase meta.md on xcc's nouns (frame reuse across
  the three ELF targets, the SSA pipeline, the riscv relocation), state exactly which calls must be
  constant-stack and which are exempt; re-run the PR/branch diff check at submit. A scope gate could
  cite GCC/LLVM sibling calls as generic prior art.
- **Maintainer optimizer branches** (`common-sub-expr`, `constant-folding`, `live-interval`,
  `peephole-opt`): re-check at submit. The SSA flag is `make test-ssa`, `xcc -apply-ssa` printed
  "unknown option": confirm the driver spelling at design time.
- **JUnit:** not native; base mode needs a log mapper, new tests one testcase per program x target.
- **Requirement 0:** check xcc in the platform repository picker before designing.
