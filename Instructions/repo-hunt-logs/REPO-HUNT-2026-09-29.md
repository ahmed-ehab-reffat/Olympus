- **Language:** Python primary; the C++ port is a major share (same language profile the platform accepted for the approved pick).

- **Competitors:** robertmuth plus ArturKlauser (4). 0 signature accounts. No AI-sweep marks.
- **Capability:** the front-end constant evaluator gains an address-constant value (global symbol + byte offset).
  - Surfaces:
    - evaluation of `@g.f`, `@g[k]`, `front(g.f)`, `pinc(...)`, chains through constant-pointer globals, and span pointers into a global;
    - compile-time `==`/`!=`/pdelta, including in `static_assert`;
    - optionally, folding a dereference of an immutable global;
    - emission of `.addr.mem <size> <name> <OFFSET>` in pointer globals, vec/rec tables and span pointers, on x64/a64/a32 (a32 pointers are 4 bytes, so record layouts shift).
  - Python and C++ must agree byte for byte; the suite already enforces this through the assimilation diff.
- **Files:** FE/eval.{py,cc,h}, FE/emit_ir.{py,cc}, FE/optimize.{py,cc}. No BE file and no opcode.
- **Self-collision / derivative:**
  - The two earlier picks are BACKEND (lowering, legalize, regs, isel, calling convention).
  - FE/eval.py is a different module from BE/Base/eval.py.
  - This lane is FE constant evaluation and data emission, a different subsystem and feature class.
  - It does not touch the Cwerg issue roadmap the foreign pipeline holds (#3, #2, #33, #10, #6, #45/#29).
  - Derivative risk: MEDIUM-LOW. "Address constants in global initializers" is nameable from C, but the hard part is Cwerg's eval-before-canonicalize pipeline and the twin parity. The visible TODO (`eval.py:807` "TODO maybe track symbolic addresses", also :879/:883/:895) is a mild magnet.

### Stage 6 death-class guard (run by me on RANK 1): PASS, with one flagged risk
1. **One shared kernel feeding several surfaces:** YES. The (symbol, offset) address value feeds data emission, compare folding, static_assert, constant-pool hoisting, copy-propagation, and py/cc parity.
2. **Interdependent traps:** YES, pairwise.
   - Emitting through canonicalized nodes (T1) forces either re-evaluation at emit time or keeping eval results across canonicalize. Either choice meets the widened classifier (T2), which routes hoisted locals through the same emitter.
   - Offsetted values break symbol-only equality (T3), which silently corrupts compare folding and copy-propagation.
   - A fix in Python alone fails parity (T4).
3. **Standalone new file?** NO. The evaluator, emitter and optimizer in two languages, with the stage order fixed by compiler.py.
4. **TOO-EASY Pre-Pick Guard:**
   - #1 (single rule at many sites): the live RISK. "Carry an offset" is one insight, but T1 (stage boundary) and T2 (hoisting classifier) are separate walls that one rule does not discharge.
   - #2 (single-subsystem fully-specified transform): multi-stage FE plus the twin, passes.
   - #3 (hardness depends on an unstated spec): no. The walls are code-hidden, and the contract can be stated in full.
   - #4 (port): no.
   - #5 (survives being spelled out): yes; cross-stage timing and parity survive.

   Verdict: PASS. Author the core slice, then take the platform precheck and a smoke batch early (the Guard #1 risk). Do not stack description-side rounds first.
