## RANK 1 dossier: robertmuth/Cwerg, compact pointer + error-code tagged unions

- Apache-2.0 (read at the 09-09 audit, nothing vendored). Python 52% + C++ 43%.
- Default branch master, HEAD `3bc94f7c1c26834f98c614aef51b5aa7370615d9` (2026-06-19). This is the same base as both accepted Cwerg picks.
- CI `cwerg-tests` green on the last 6 master runs.
- 25 open issues, all maintainer roadmap. 0 open PRs, 9 PRs ever, the only branch is master, forks are not ahead.
- No signature accounts, no AI trailers.
- **Our submission count:** 3 (cwerg-bcopy-bzero-lowering ACCEPTED, cwerg-fe-address-constants ACCEPTED 2026-10-11, cwerg-memory-passed-parameters REJECTED as derivative). This is a warning only.

**Capability:** make a tagged union of exactly one pointer plus void or wrapped-void (error-code) members occupy one pointer word on every target, with every union operation still working. Those operations are widening, narrowing, `is`, tag and `==` comparisons, trylet, records, globals and calls. This is the representation the repo's disabled `optimize_union_tag` flag only sizes.
- Outsider summary: "lay out optional-pointer / error-code unions as one machine word in Cwerg's front ends."
- The concept can be named (Rust niche, Zig `?*T`). The implementation is Cwerg's union desugaring in twin front ends.
- The multi-error-code case has no null-niche analogue.

**Gate 1 (argued from code and run on base, Python FE, x64):**
- `design_choices.md:210` promises a "special optimization for optional pointers so that nullable pointer can be implemented efficiently".
- `type_corpus.py:243/311` and `type_corpus.cc` size the union as one word only when `ta.optimize_union_tag` is set. Every STD_TARGET sets it False (`type_corpus.py:219-221`, `type_corpus.h:44-46`).
- `canonicalize_union.py:43-55` always builds the `{tag, union}` record, so `size_of(union(void, ^T))` is 16 on x64.
- The repo's own tests state the target: `LangTest/sizeof_test.cw:69/74` ("half the size with union optimization") and `linked_list_gen_test.cw:32` ("should be (* N 16) on 64 bit system with union optimization").
- Flipping only the flag compiles and then silently miscompiles: the record layout uses 8 while the replacement record is 16. The linked_list test traps; the other probe cells pass.

**Missing machinery:**
- a one-word replacement type;
- an encoding of the zero-size members that cannot collide with a pointer (the sketch stores the member's typeid, which is < 2^16);
- tag extraction;
- the widen/narrow matrix between compact, regular and zero-only unions.

**Written sketch (agent, my re-measure):**
- `sketch_Cwerg_compactunion_h63.patch`: hook raw 384, **human-effective 304** (canonicalize_union.py 116, canonicalize_union.cc 178, plus wiring in type_corpus.{py,h} and compiler.{py,cc}), padding-floor 116. The padding-floor is low because the C++ twin mirrors the Python; the accepted address-constants lane had the same profile at slice (251/133) and was accepted at 365.
- The Python half was run end to end on x64: 50 of 51 FE `*_test.cw` pass. The one failure is sizeof_test, whose static_asserts pin the old sizes; that is an intended test update.
- Probes compact_test, ll_test and gl_test pass.
- The C++ half is written but NOT compiled.

**Traps (interdependent, misdirecting):**
1. **Identity corruption (F-2/F-75 family).** The natural design replaces the union by `^T`. `LinkReplacementType` (cwast.py:1067) then sets `original_type`, and `get_original_typeid` (cwast.py:1016) returns the union's id for `^T`. Later widenings of `^T` into regular unions then carry the wrong tag, and `is()` fails far from the compact code.
2. **Several zero-size members (F-10).** A null-only niche fails `union(err1, err2, ^T)`, which the type_corpus hack already sizes as one word.
3. **Layout vs replacement (F-9/F-1).** The layout is fixed at typify and the replacement happens later. The silent record overlap shows up as a wrong field value.
4. **Stage boundary (F-75).** `Expr3` is eliminated before union replacement (compiler.py:337), and the bitcast verifier rejects union operands (type_corpus.py:124). The resulting asserts name the checker, not the union code.
5. **Conversion matrix and twin parity (F-10, F-31).** Python and C++ must emit identical IR.

**Stage 6 death-class guard (run by me):**
- Q1 one shared kernel: YES. One representation feeds tag/is/==/trylet, narrow, widen, layout and calls.
- Q2 interdependent: YES. Encoding is tied to tag extraction and the zero-only conversions; replacement identity is tied to widen-into-regular tags; layout is tied to replacement size.
- Q3 standalone file: NO. The edits sit inside the existing union replacement, type_corpus and compiler.
- Q4 TOO-EASY Pre-Pick Guard:
  - Not membership/validation, not a uniform wrap, not a saturated port.
  - The SELECTOR is met: the identity-link wall and the Expr3 stage wall are emergent repo-architecture walls that survive full specification.
  - "Make X consistent with an existing correct Y" does not apply, because no in-repo sibling has a compact representation.
  - #1 holds partly (a conversion family), and the hidden walls carry it.
- **Guard: PASS.**
