### Verified F2P gap (Gate 1 + Gate 6, reproduced on base)

1D fixture (11 nodes, `dw_laplace` eps=1e-2 + `dw_volume_nvf` with g(T)=T^3-3T, minus
`dw_volume_lvf` with the load read from `ts.time`, natural BCs). The uniform solution satisfies
T^3 - 3T = lambda, so the analytic limit points are **lambda = 2 at T = -1** and **lambda = -2 at T = 1**.
`ts.simple` from T = -sqrt(3), lambda 0 to 3:

```
 1.900  -1.1774
 2.000  -1.0000      <- exactly the analytic fold
 2.100  -0.9999      <- Newton did NOT converge; ts.simple accepted it anyway
 2.200   2.0222      <- jumped to the far branch
```

No solver in sfepy can turn at a limit point, so every quasistatic problem with softening (the
repo's own `balloon.py` Mooney-Rivlin inflation, snap-through) has to be driven by a prescribed
kinematic quantity instead. `balloon.py`'s docstring says as much: it prescribes the volume change,
and carries the analytic pressure-stretch relation p = 4 h0/r0 (1/L - 1/L^7)(c1 + c2 L^2), which is
non-monotone for its own c2/c1 = 0.1. That is a second in-repo analytic oracle. Probe script:
session scratchpad `_probe_fold.py`, 2 s runtime.

### Missing machinery (Stage 3b)

`nls.Newton` solves f(x) = 0 only. Nothing in the repo does a bordered or augmented solve, holds a
load factor apart from time, adds a constraint equation, selects a quadratic root, or detects a limit
point. The algorithm the repo lacks: **a predictor-corrector path follower over (u, lambda) with an
arc-length constraint**, driven through sfepy's own load model (`Problem.time_update` refreshes
materials AND essential BC values from `ts.time`).

### Phase-3 death-class guard

1. **Shared kernel:** the residual at (u, lambda) plus the rollback feed predictor, corrector,
   rejection, target landing and output. Applying lambda only to materials passes the force cells and
   breaks the EBC cells. Applying it through `time_update` without a rollback breaks the rejection cells.
2. **Interdependent:** landing exactly on the target lambda needs a lambda-controlled last step that
   fights the arc constraint and touches the rollback. The direction rule depends on the increment
   norm, which depends on which DOFs count (reduced free DOFs vs full vector under EBC/LCBC).
3. **Standalone new file?** Partly. It registers as a `TimeSteppingSolver`, which is the missing-arm
   shape, but the arm carries new mathematics and ~250+ eff (the sibling is ~60). **Watch this at
   authoring.** If the reference drops under 250 eff, add the path query object, don't pad.
4. **TOO-EASY guards:** no famous-language-feature, not a port, no open issue magnet. The algorithm is
   textbook, so difficulty must come from the sfepy integration cells, not the corrector math.

## The pick — featurevisor minimum-disruption rebucketing

`problems/featurevisor-minimal-rebucketing`, base `b88f398` (v3.11.0), MIT, TS, 807 stars, 0 open
PRs, no signature accounts, CI green, quota 0/6.

Today `getTraffic` preserves bucketed users ONLY when a rule's percentage increases; a decrease, a
weight change, an added/removed variation or rule `variationWeights` refill from scratch and churn
users for no reason. The slice replaces that with one range kernel: keep each variation's own bucket
values that still fall in the rule's region (lowest first, up to its new target), free the rest, fill
deficits from free space in declaration order, then sort and merge.

- **Own-model:** the region is featurevisor's allocation-range + slot-range model; GrowthBook's
  sticky bucketing is an SDK per-user store, not range reallocation. No public equivalent found.
- **Two latent repo bugs on the same seam** (left for later scope): state is persisted WITHOUT
  `ranges`, so `detectIfRangesChanged` can never fire; and `getUpdatedAvailableRangesAfterFilling`
  silently drops later untouched ranges (bites grouped features with several slot ranges).
- **Boundary trap:** allocations match inclusively at both ends, the flag check is a prefix
  (`bucketValue <= percentage`), and group ranges are half-open — so "trim each variation from its
  top" is wrong whenever those tops sit above the new percentage.
- **Validated:** base 1040/1040 (3x), new 31/31 (3x), 14 of 31 fail on base, typecheck/eslint/
  prettier clean, uid 1000, `--network none`.
- **Open risk:** 160 effective LOC, below the 200 auto-block — the owed scope (group slot semantics,
  `ranges` persistence, CLI surfacing) must land before submission.
