### Absorption test (Stage 3b) — the decisive result

Named-algorithm probes over all 20,660 LOC:

```
reloc|linker|linking|external symbol|translation_unit|object_file  -> 0 hits (only `extern "C"` wasm/FFI)
free_space|placement|place_|allocat|bin_pack|layout|auto_addr      -> 0 hits
```

`#bankdef` accepts only explicit constants — `bits`, `labelalign`, `addr`, `addr_end`, `size`,
`outp`, `fill`, `data` (`src/asm/parser/directive_bankdef.rs:40-68`) — and `Bankdef` stores
`addr_start: BigInt` plus `output_offset: Option<usize>` set by hand
(`src/asm/defs/bankdef.rs:5-16`). `src/util/overlap_checker.rs` (114 LOC) only **validates** a
hand-written memory map after the fact. **The assembler can check a memory map but cannot compute
one.** That is missing machinery, not a missing dispatch arm.

### Best Olympus theses (ranked; each still owes author-phase Phase 2)

**L1 — Bank placement solver (RECOMMENDED).** Let banks declare constraints (a region, alignment,
a max size, an ordering or overlay relation) instead of a literal `addr`/`outp`, and compute the
placement. New algorithm: constraint-driven placement plus free-space accounting, run INSIDE the
existing fixpoint because variable-size encodings mean a bank's size is not known until encodings
settle, while encodings depend on addresses that depend on placement. Spans
`asm/parser/directive_bankdef.rs` -> `asm/defs/bankdef.rs` -> `asm/resolver/{mod,addr,iter}.rs` ->
`asm/output/mod.rs` -> `util/overlap_checker.rs`. **Magnet-clear: no issue asks for it**
(#195 asks only for read-only `firstfree` SYMBOLS). Absorption-clear. Interdependence is
structural, not bolted on.

**L2 — Whole-ruledef-set encoding analysis.** Symbolically enumerate the encodings a ruledef tree
can emit and report collisions/ambiguity independent of any source program. `RuledefMap`
(`asm/defs/ruledef_map.rs`) is only a 4-char prefix index for match speed, so the analysis is
absent. ⚠️ **Two hazards:** self-collision with our approved `customasm-ruledef-disassembly` (also a
whole-ruledef-set analysis), and Gate 8 — on #121 the maintainer wrote *"it's important that the
assembler doesn't choose any one rule based on order -- in the future it would allow for new
optimizations"*, which reserves the lane.

**L3 — Relocatable output + linking (#48). DOWNGRADED, contra the `TOO-EASY.md` note that
suggested it.** Absorption is clear and the LOC would be genuine, but the tracker probe kills it as
a Stage-2b magnet: the thread carries **two published design sketches** (`theorzr`'s `#obj <format>`
block; `Phlosioneer`'s full `#external` upper-bound/alignment design, 2022-08-30), the capability is
externally named (ELF/COFF/relocation), the request is six years old with no PR — the "two-year-old
invitation is a queue" profile — and the maintainer moved the design discussion to **Discord**
(2022-09-26), so philosophy is being formed where the SIX-CHECK cannot see it.

## Method notes worth keeping

1. **⭐ The tracker probe at RANK time did its job on its first outing, and it OVERTURNED a written
   lead.** `TOO-EASY.md`'s customasm entry closes by recommending "relocatable output + linking,
   informed by issue #48" as the next pick there. Four minutes of `gh issue view --json body,comments`
   showed #48 carries two published design sketches, an externally-named capability, and a maintainer
   who moved the discussion to Discord. The lead was demoted from the recommendation to L3. **A
   recommendation recorded in our own docs is not a cleared lane — it is a lead that still owes the
   probe**, exactly like an issue title.
2. **⭐ Cold GitHub keyword sweeps are now near-worthless and should be skipped.** Every domain
   keyword (`mesh`, `compression`, `cryptography`, `kinematics`, `codec`, `routing`, `scheduling`)
   returns an LLM/AI-infrastructure result set — `Mesh-LLM`, `llm-compressor`, `KVCache-Factory`,
   `solace-agent-mesh`, `DeepSeek-OCR`. The star-ranked head of GitHub has been colonised. The
   scientific/obscure repos this skill wants no longer rank in a star-sorted keyword search. Combined
   with the 30-searches/minute secondary limit that silently empties a batched sweep, the proven-pool
   re-mine is not merely the higher-probability path any more, it is close to the only one. Budget the
   time into Requirement 7 + 2b-bis on pool repos instead.
3. **Requirement 7 is the highest-yield gate in the file, second session running.** It killed four
   candidates here (canvas, whitebox-tools, pysteps, vrp) for one API call each, including canvas,
   which was otherwise heading for RANK 2. ⚠️ **Read the JOB and STEP names, not the run conclusion**
   — canvas's failing run needed `gh api .../jobs` to show the failure was the step "Tests with
   coverage" rather than a lint or a benchmark. And treat `action_required` as "no evidence", not as
   neutral: vrp has workflows that are never approved, so its suite has never been observed passing.
4. **The competitor swarm has gone from a signature to a wave.** Three separate pool repos
   (python-control, agate, pydata/sparse) are now saturated with one-bug `fix:` PRs from mutually
   unrelated fresh accounts, with `binggao1230` merged in ALL THREE and `ChrisJr404` in one. On
   python-control the maintainers merged an explicit AI-contribution policy doc. Profiling is no
   longer about spotting one scatter account; count the fraction of the 12-month PR stream that is
   surgical one-bug fixes from accounts with no domain footprint. Above roughly a third, treat the
   repo's whole gap surface as mined.
5. **A prior rejection's REASON decides whether the repo survives it.** `openpnm-robin-boundary-conditions`
   died on local calibration (too easy) -> the repo lives. `twelvemonkeys-sgi-writer` died on the
   plagiarism gate and `go-mp4-sample-locations` on cross-repo overlap -> those repos' natural pick
   shapes are dead. Read the closure record before re-mining any repo in `rejected/`.
