### Lane
pint today knows a query's value only when the whole sub-expression is a constant: `KnownReturn` plus `calculateStaticReturn`, at source.go:1259 and :1721. The lane adds a value range to every source and uses it in three checks:
- **promql/impossible:** report a comparison that can never match, for example `rate(x[5m]) < 0`, `count(up) == 0` or `x > 5 < 3`.
- **promql/nan:** treat a divisor as safe exactly when its range excludes 0. This replaces the ad-hoc `excludesZero` and `clampExcludesZero` helpers (promql_nan.go:291-347).
- **alerts/comparison:** report an alert whose comparison is always true, for example `count(up) >= 1`.

The ranges come from number literals, unary minus, `+ - * / % ^`, a capped function and aggregation table, and comparison narrowing in every vector-matching branch.

### Gate 1 (static; the runtime script is in hunt #47's dossier `agents/ir-1002H47.md`)
The only producer of comparison DeadInfo is `calculateStaticReturn`, and it runs only when both sides are `KnownReturn`. That gives these results on base:
1. `rate(errors_total[5m]) < 0`: promql/impossible reports nothing.
2. `count(up{job="x"}) == 0`: nothing.
3. `sum(a / (5 > b))`: promql/nan reports nothing, a real false negative.
   - `checkConditions` records `Condition{GTR, 5}` on `b` (source.go:1611-1641), so the orientation is lost.
   - `excludesZero` then calls the divisor safe, yet `b = 0` passes `5 > b`.
4. `sum(a / (clamp_min(b, 1) - 1))`: nothing. Binary ops are not recorded in `Operations`, so the clamp still reads as safe.
5. Alert `count(up) >= 1`: alerts/comparison is silent because `Condition.Present` is set.

The runtime F2P check is OWED. It needs Go 1.27.

### Traps (interdependent; they share the `binaryRange` kernel)
1. **Operand orientation.** This applies to a scalar on the left of a comparison (`5 > b`), to arithmetic where the result source is the RHS (`1 - x`, `1 / x`), and to the `group_right` branch, where the result is `rs` but the value is `ls OP rs`.
   - The natural local fix flips `Condition.Op`. That rewrites 94 `condition:` entries in `source_test.snap` and changes promql/series and alerts/template inputs (F-12, misdirecting).
   - The failing nan test points at promql_nan.go, but the cause is in source.go.
2. **Range at the time of the operation versus the final range.** nan must read the divisor's range where the division happens.
   - Example: `sum(1 / bar)`. Reading `s.ValueRange` after the division (or after `sum`) gives the quotient's range instead of the divisor's.
   - This is an F-9-style snapshot that the repo's `Indirect` and `Join` records do not carry today.
3. **Aliasing across RHS sources.** The one-to-one branch loops `for rs := range rhs` and mutates `ls` in place (source.go:1308-1312). With `a / (b or c)`, narrowing or arithmetic compounds unless the original range is kept and the per-RHS results are unioned (F-4/F-34).
   - The nil-matching branch clones per RHS, so the two branches behave differently.
4. **Coexistence with constant folding.** These existing messages must stay byte-identical:
   - `vector(1) > 2` and `0 > bool 0` in promql_impossible_test.go, plus the existing `describeDeadCode` text;
   - alerts/comparison already skips any source with DeadInfo, so a range-based DeadInfo silently moves a rule from one check to the other (F-20 sibling contamination).
5. **Chained conditions.** For "always true", every comparison on the source must be always true. `count(x) > 0 < 100` is not always true. Agents that set the flag from the first comparison only, as `checkConditions` does for `Condition`, get it wrong (F-27-like).
6. **Snapshot preservation.** Every Source is YAML-snapshotted with go-snaps. A range field without `yaml:"-"`, or exported with non-zero values, breaks hundreds of base snapshot assertions (F-12).

**F-10 cells:** comparison × `bool` × operand side × inside/outside an aggregation (nan's Depth gate, promql_nan.go:209) × matching kind (nil, one-to-one, group_left, group_right).
