### Missing machinery (Stage 3b)

The repo has no memory-passed parameter or result, no caller-side outgoing-argument area, and nothing
that computes a signature's register/memory split. Algorithm the repo lacks: **a per-target signature
split into register and memory parts, with a caller-built tail block and a callee that loads from it**,
kept consistent across the three consumers of the split.

The three consumers (the F-9 seam):

1. `FunPushargConversion` (caller side, reverse pass, `lowering.py:676` / `lowering.cc:732`)
2. `FunPopargConversion` (callee side, forward pass, `lowering.py:643` / `lowering.cc:764`)
3. `fun.cpu_live_in` / `cpu_live_out` (`legalize.py:218/246/259`), which the live-range builder in
   `liveness.py:303+` uses to reserve registers across a call. Liveness proper ignores `cpu_live_in`
   (commented-out TODO at `liveness.py:70,102`), so a rest pointer missing from the live-in set is not
   an assert. It can be handed to a temporary between the argument move and the call. **Confirm with a
   mutation at authoring:** if it miscompiles silently under qemu, that is the misdirecting lead trap.

Sketch (calibration: the approved bcopy pick measured 690 human-effective over 19 files on the same
py + cc x 3-target layout):

| Piece | eff (py) | eff (cc) |
|---|---|---|
| signature split per target, incl. the register the rest pointer itself consumes, A32 R64 pair alignment | 35 | 45 |
| caller: one stack object sized to the largest tail in the function, per-kind alignment, `st.stk` stores, `lea.stk` into the rest register | 45 | 60 |
| callee: capture the rest pointer, `ld` each tail parameter at its offset | 25 | 35 |
| live-in / live-out sets and legalize wiring x 3 | 20 | 30 |
| results direction (optional scope-up): caller-provided result block, whose hidden pointer consumes an input register | 40 | 55 |
| **total** | **~125-165** | **~170-225** -> **~300-390 eff core, ~390 with results, >= 10 files** |

Above 250, so it proceeds. Scope-up if the reference lands short: the results direction, then an FE

### Phase-3 death-class guard

1. **Shared kernel:** the signature split feeds caller, callee and the live sets on every target. A
   local fix on the caller side that disagrees with the callee side miscompiles every call.
2. **Interdependent:** the rest register changes which parameters spill (boundary); R64 pair alignment on
   A32 shifts FLT slots; a result block pointer shifts the input split. Fixing one moves the others.
3. **Standalone new file?** No. It has to edit existing passes in every backend and both languages.
4. **TOO-EASY guards:** not a language-surface feature (backend ABI, invisible to the Cwerg language), not
   a port, and the self-collision with the approved bcopy pick is file-level only (same `lowering` +
   `legalize` files, different capability; no recorded reject on file overlap without capability overlap).
