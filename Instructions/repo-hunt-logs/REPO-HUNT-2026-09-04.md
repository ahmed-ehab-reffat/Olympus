  (`:1344`) and `SpatialInterpolatorConstantRotation` (`:1418`) all carry `# pragma: no cover`, and

- **Previously dead:** moving sources / trajectory beamformers in a flowing medium (absorbed, ~35-45
  eff LOC — `SATURATED-REPOS.md § B2-ACOULAR`), directivity (closed draft PR #536), sector-object
  support, periodic trajectories, frequency-dependent `Calib`.
- **Remaining named lead, with a new absorption caveat:** time-varying partitioned convolution for a
  source moving through an impulse-response field (`PointSourceConvolve` + `TimeConvolve`). Measured
  this session: `TimeConvolve` (`tprocess.py:2713`) **already implements uniformly-partitioned
  overlap-save with cached frequency-domain kernel blocks** (`_kernel_blocks`, `_block_size`), so the
  partitioning half is present. The invention has to be the IR-field model plus the position-dependent
  kernel interpolation law — and that law is author-chosen, so Gate 8 requires stating it fully in
  `meta.md`. Sketch the diff before scope-locking.
- **Harness rule (unchanged):** never add a new `Generator` subclass — `tests/regression/test_generator.py`
  auto-snapshots every subclass and a new one reds base mode. Add default-off traits to existing classes.

## RANK 3 — cloudflare/wirefilter (Rust, filter-expression engine) ★1156

Best REPO hygiene in the whole sweep and the weakest remaining CAPABILITY surface.

- MIT, 18.2k LOC engine, 17 commits/180d, and Stage 2c classifies BOTH streams as **maintenance**
  (deps, clippy, rustfmt, perf: "Add fast path for Maps in map_each", "Avoid cloning in
  `Array::filter_map_to`"). PR authors are only `marmeladema`, `utkarshgupta137` and dependabot — **no
  competitor signature at all**. Quota 1/6.
- **But our own approved `wirefilter-dynamic-operands` ate the surface.** It generalised operands,
  `in`, `contains` braced sets, whole-array/map equality, computed indices, `[*]` interaction and
  no-value semantics. Every hit from the S-E restriction grep (`LexErrorKind::UnsupportedOp` in
  `scheme.rs:1573-1785`, `ast/field_expr.rs:319-390`, `ast/logical_expr.rs:952`) sits inside that
  consumed surface, and the one restriction the approved `meta.md` explicitly leaves open —
  *"regular expression and wildcard patterns still have to be literals"* — is a direct extension of
  our own submission, i.e. self-collision.
- **Architectural caveat:** the engine compiles filters into closures (`CompiledExpr`), so any
  analysis/inversion capability (witness generation for a filter, field-usage accounting, residual
  partial evaluation) has to run over the public `FilterAst` and degrades into a standalone post-pass
  — the explicit Phase-3 guard #3 reject, and the class that killed lyon T1.
- **Only worth revisiting** if a thesis lands in `functions/`, `list_matcher.rs`, `execution_context.rs`
  or `scheme.rs` registration rather than the comparison surface.

## Method notes worth keeping

1. **The proven pool is ~90 repos, not the 14 the skill's Stage 0-bis table lists.** That table was
   measured 2026-09-01 against a smaller view of the corpus. Rebuild it from
   `approved-problems/ problems/ rejected/` at the start of every hunt.
2. **A moved crate path reads as a corpse.** `gh api repos/O/R/commits?path=X` returns an empty list
   for a path that no longer exists, with no error. calyx scored 0/0/0/0 across its whole compiler
   until the tree was re-listed. Resolve the current tree before believing any per-path heat number.
3. **`# pragma: no cover` plus a `DeprecationWarning` is a lane-death signal as strong as an open PR**
   — and it is free to check. Grep the target subsystem for both before the seam audit.

## ⚠️ ADDENDUM 2026-09-05 — RANK 1 (calyx) DIED AT AUTHOR PHASE 2, 0-for-4 ON LANES

Taken into `olympus-author` the next day. Phase 1 passed (architecture, subsystems, entanglement
zones, runt+cargo harness, and the approved pick's `test.sh` reusable almost verbatim). **Phase 2
killed it, four times over** — see `SATURATED-REPOS.md § B2-CALYX` for the full evidence:

| Lane | Death |
|---|---|
| Static components + comb groups (the log's own best lead, L1) | maintainer philosophy, issue #1785 *"disallowed in a static domain"*, plus a published workaround design and merged PR #2596 next door |
| FIRRTL `@external` (L2) | a downstream-toolchain limitation by design, plus roadmap #1805 |
| Statistics / area accounting (S-F) | SHIPPED — #1184 closed by #1372, in-tree as `backend/src/resources.rs` |
| Resource-budgeted cell sharing (S-G) | maintainer-claimed in #2021, and `-x cell-share:bounds` already exists |

**What this corrects in THIS hunt's own method.** Every ranking signal I used was a COMMIT-STREAM or
CONTRIBUTOR signal: per-path heat, PR-author profiling, both-streams classification, CI health. None
of them can see a tracker. For a repo whose maintainers publish roadmap issues and claim lanes in
comments, the tracker IS the gate, and it is invisible to the entire Stage 2c/2b-bis apparatus.

**Method change for the next hunt: add a fifth mechanical probe at RANK time, not at author time.**
Before writing a candidate's dossier, sample 3-4 plausible lanes against the tracker
(`gh issue list --search` on the lane keyword, then `gh issue view --json body,comments` on every
plausible hit). Cost: about four minutes. It would have moved calyx off RANK 1 before it was written
down, and it is the same money as the Stage 2b "read issue BODIES not titles" rule, applied one stage
earlier and to the REPO rather than to a single pick.
