- **Self-collision:** no prior submission anywhere in this workspace touches binary-format parsing

- **Missing machinery (LOC carry):** confirmed by direct source inspection, not inference. Modern
  Mach-O binaries (effectively all macOS/iOS binaries shipped in the last ~5 years) resolve their
  dynamic imports via `LC_DYLD_CHAINED_FIXUPS`, not the legacy `LC_DYLD_INFO(_ONLY)` bind-opcode
  stream that `mach/imports.rs::BindInterpreter` implements. `load_command.rs:1701-1704` recognizes
  the `LC_DYLD_CHAINED_FIXUPS` command **only as a generic `LinkeditDataCommand`** (an offset+size
  pair) — `grep -rniE "dyld_chained|chained_starts|chained_ptr" src/` returns **nothing**: the
  `dyld_chained_fixups_header`, `dyld_chained_starts_in_image`, `dyld_chained_starts_in_segment`,
  the per-page pointer formats (`DYLD_CHAINED_PTR_ARM64E`, `DYLD_CHAINED_PTR_64`), and the chained
  imports table are **entirely unparsed**. This is new machinery, not a call-through — the repo owns
  none of the pieces.

**Confirmed, external, uncontested evidence of the gap (all read directly, none of these are the
pick itself — see the magnet warnings below):**
- **Issue #323** (opened 2022-08-24, still OPEN, last activity 2024-07-29, zero PRs against it):
  reporter hits `index out of bounds: the len is 3 but the index is 17` at `mach/imports.rs:103`
  (`libs[bi.symbol_library_ordinal as usize]`) parsing a real arm64e system binary
  (`/usr/bin/lpoptions`). Maintainer's own comment explicitly REJECTS the cheap fix
  (`libs.get().unwrap_or("")`) as "just mask[ing] the underlying issue" — i.e. the maintainer has
  already stated in public that the real fix is architectural, not a bounds check.
- **Issue #542** (OPEN, filed with a full PoC and root-cause diagnosis, `mach/imports.rs:94`,
  `segments[bi.seg_index as usize]` unchecked) corroborates the same underlying "modern bind data
  isn't understood correctly" class from a second, independent angle (a crafted 79-byte file with
  an empty `segments` list plus a 89-byte file that OOMs `symbols()` via unchecked `nsyms`).
- `tests/macho.rs` (649 lines) **never calls `.imports()` on anything**, and `tests/bins/` has zero
  Mach-O fixture files — this exact code path has no regression coverage at all on base.

**Why these are corroborating evidence, not the pick:** #542 in particular reads like a finished
bug report (exact PoC bytes, exact line numbers, root-cause diagnosis already written out) — treat
it as a magnet under Stage 2b, not a gift. Do not scope the problem as "fix the two bounds checks
issue #542 names." The actual pick (adding real `LC_DYLD_CHAINED_FIXUPS` parsing so `imports()` and
`symbols()` resolve correctly on modern binaries instead of silently returning nothing or indexing
garbage) is a superset that subsumes both reported symptoms without touching either issue's exact
described fix, and "chained fixups" is Apple/dyld-internal machinery with no textbook name — low
external-spec magnet risk on its own terms.

**TRAP SEAMS (failure-patterns.md):**

| Pattern | Present | Evidence |
|---|---|---|
| F-1 convergent-architecture wall | **yes** | `load_command.rs:1701-1704` — the load-command stage only ever hands downstream code an offset+size pair (`LinkeditDataCommand`) for `LC_DYLD_CHAINED_FIXUPS`; every actual structure (header, per-image starts, per-segment starts, per-page chains) has to be built fresh from raw bytes with no existing scaffolding to lean on |
| F-9 cross-stage resolution drop | **yes** | `mach/imports.rs::BindInterpreter` (the "resolving" stage) only ever reads the legacy bind-opcode range; the load-command "validating" stage (`load_command.rs`) already recognizes and stores the chained-fixups command's offset/size but never routes it anywhere — the exact validate-vs-emit split F-9 targets |
| F-10 capability cross-product | **yes** | two real, independent format axes inside chained fixups: pointer-format axis (`DYLD_CHAINED_PTR_ARM64E` vs `DYLD_CHAINED_PTR_64`, different bit layouts for the bind/rebase discriminator + ordinal) and imports-table-format axis (`DYLD_CHAINED_IMPORT` vs `..._ADDEND` vs `..._ADDEND64`, different per-entry widths) |
| F-13 two-tier format (base + amendment) | **yes** | `dyld_chained_starts_in_image` (base: one entry per segment, an offset into...) -> `dyld_chained_starts_in_segment` (per-segment: page_size + page_count + `page_start[]` array) -> per-page chain walk (each page's chain is itself a linked list via an embedded "next" delta) — three literal tiers, each amendable/overridable independently, exactly the rust-minidump-class shape that was the top measured killer (6/10) |
| F-14 declared-vs-derived terminal state | **partial** | the chain-walk terminates on a sentinel `next == 0` delta and must also treat malformed/self-referential chains as a stop condition without infinite-looping — a natural place to add a declared terminal state alongside the format's own implicit one |
| F-2 bidirectional seam | **yes** | `BindInterpreter`'s existing legacy-format state machine already IS a stateful accumulator (`BindInformation` carries fields across opcodes, reset on DONE) — the new chained-fixups path needs an analogous but differently-shaped piece of running state (an ordinal table populated once, then indexed many times during the chain walk), and the two paths must ultimately merge into one `imports()` result without cross-contaminating state |

**Best Olympus feature thesis:** parse `LC_DYLD_CHAINED_FIXUPS` for the two mainstream pointer
formats (`DYLD_CHAINED_PTR_ARM64E`, `DYLD_CHAINED_PTR_64`) and the uncompressed imports-table
formats, walk the per-segment/per-page chains against the already-parsed `segments` data, and make
`imports()` (and ideally `symbols()`'s companion resolution) return correct, complete results on
binaries that use chained fixups instead of legacy bind opcodes — spanning `mach/load_command.rs`
(new struct definitions + real parsing instead of the generic `LinkeditDataCommand` stub),
`mach/bind_opcodes.rs` or a new sibling module (chained-fixups constants), `mach/imports.rs`
(the second execution path + the merge point), and `mach/mod.rs`/`MachO` (wiring). Cross-package in
the sense that mirrors our shape taxonomy (load-command stage -> segment data -> import resolution),
all inside `mach/` — single-subsystem, Olympus-viable without needing to reach into `elf/` or `pe/`.

**Estimated complexity:** 400-550 effective LOC across 4-5 files in `mach/` (`load_command.rs`,
a new `chained_fixups.rs` or extension of `bind_opcodes.rs`, `imports.rs`, `mod.rs`, plus test file).
Not yet measured against Counter 2 — sketch the minimal correct slice (one pointer format + one
imports format, faithfully) before scope-lock rather than assuming the ceiling estimate holds.

**Why it matches:** exactly the brief (a real multi-stage binary-format pipeline, Rust, obscure-to-
problem-authors domain — nobody picks Mach-O chained-fixups internals for a coding problem), a
confirmed real behavioral gap with two independent external bug reports as corroboration, zero
open-PR contention on the target files, zero regression coverage on the target code path today, and
a repo whose own test conventions already prove synthetic binary fixtures are normal here.

**Risks:**
- **(a) Scope discipline.** The full chained-fixups spec has more pointer formats and a compressed
  (zlib) symbols format; do not chase completeness. Scope to the two pointer formats + uncompressed
  imports table explicitly, and say so in the description as the stated boundary (not a hidden one).
- **(b) Gate 1 still owed as a measurement**, not just a source-read. Build one synthetic arm64e-style
  chained-fixups Mach-O (following the repo's own inline-byte-array test convention) and confirm
  `imports()` on base actually returns wrong/empty output rather than an error the crate already
  surfaces cleanly.
- **(c) The two corroborating issues are magnets on their OWN exact fix** (bounds-check patches) —
  keep the meta.md description scoped to "parse chained fixups correctly," never to "fix the OOB
  panic in imports.rs" or cite either issue's line numbers, or the pick reads as directly solving a
  publicly-diagnosed bug rather than as adding the missing capability.
- **(d) Determinism/build-order:** `test.sh` must run `cargo build` before `cargo test` (or equivalent)
  so `archive::parse_self` doesn't spuriously fail — documented above, not a blocker, just don't skip it.
- **(e) Docker unverified locally** (no local Docker on this workstation) — plain-Rust `cargo test`
  with three pure deps should be low-risk, but confirm on the platform run before treating it as closed.
