# Repo hunt 2026-08-04 — targets that can carry a HARDENABLE design

Brief: find repos whose seams give `olympus-harden` room to work (a real lever to pull when a
batch reads soft), while avoiding every death class in `TOO-EASY.md`.

Prior state carried in: `REPO-HUNT-2026-08-02-C.md` left calyx as RANK 1 with candidates 1 and 3
killed (Gate A / Gate 6) and candidate 2 likely sub-floor. This sweep looked for fresh repos.

**The hardenability test used here** (derived from `failure-patterns.md` § 5 + `HARDENING.md`):
a repo is hardenable only if, when a batch comes back >40%, there is a lever LEFT to pull that is
not "add more rules". In practice that means the repo must offer at least one of
F-1 (a stage that destroys information), F-9 (validate-here / emit-there), or F-2 (a producer-AND-
consumer construct driving a fixed point). F-10 cells are free everywhere and are not a
differentiator between repos.

**Trap seams**

| Pattern | Present | Evidence |
|---|---|---|
| F-1 convergent-architecture wall | **yes** | shaping reorders/substitutes glyphs (`scripts/indic.rs` 3887) before any later stage sees them; a post-pass over the shaped glyph stream structurally cannot recover pre-reorder cluster identity |
| F-9 cross-stage resolution drop | **yes (strongest)** | `subset.rs` must compute glyph closure THROUGH `gsub.rs`/`layout.rs` lookups; the layout tables resolve coverage independently at shape time, so both placements look reasonable — the textbook F-9 ambiguity |
| F-2 bidirectional seam | **yes** | mark-attachment / cursive positioning: a glyph is both anchor and attachee; ligature formation then decomposition |
| F-10 cross-product | **yes** | axes: table format variant (single vs multiple coverage / format 1 vs 2) x direction (LTR/RTL, pre vs post base) |
| F-8 named-algorithm override | **yes, but see risk** | OpenType/HarfBuzz semantics are famous; allsorts diverges in documented places |

**Honest risks (all Gate-A owed work, none cleared yet):**
1. **Derivative (Stage 2b).** Anything nameable by the OpenType spec ("add COLRv1", "variable-font
   instancing", "add script X shaping") is a MAGNET — reject those on sight. A viable pick must be
   phrasable only in allsorts' own nouns (its subsetting closure, its cluster model).
2. **Saturated-reference risk.** HarfBuzz semantics are heavily represented in training data — the
   same axis that makes F-8 available makes a faithful-spec pick a `js-joda` death.
3. Test style + baseline determinism NOT yet verified (golden-font fixtures; needs a 3x run).

## Gate A kill-test on allsorts (run 2026-08-04) — DEAD, repo goes to § B2

Build/test mechanics all passed: `cargo test --no-default-features --features flate2_rust` builds in
84s and runs 776 tests green, deterministic, no external services.

**The candidate came from the repo's own conformance suite and it was fool's gold.**
`tests/aots/testcases.rs` has ~35 `#[ignore]`d cases reading "cursive anchor positioning is not yet
implemented" / "mark positioning is not yet implemented" / "vertical advance is not yet implemented",
and `cargo test --test aots -- --ignored` confirms **0 passed / 35 failed**. That looks like a
ready-made f2p gap with in-repo evidence.

It is not. `src/gpos.rs` implements every GPOS lookup type, and `src/glyph_position.rs` (619 lines)
is a complete multi-pass resolver — cursive-chain pass, then mark pass, direction- and
vertical-aware. `tests/aots.rs:255` hand-rolls its own position loop that only understands
`Placement::Distance` and never builds a `GlyphLayout`, so allsorts' symbolic
`Placement::{MarkAnchor, MarkOverprint, CursiveAnchor}` resolve to nothing. **The tests fail for
harness reasons; the library is correct through its public API.** Gate 1 fails — no observably
wrong output.

**Third instance of the STALE-MARKER law**, after taffy's stale grid-baseline TODO and calyx's
defensive `unreachable!`: an in-repo marker claiming a feature is missing is a candidate GENERATOR,
never a validator. Cost here was ~15 minutes because the check was run before authoring.

Full entry with the recorded assets (the Uniscribe-not-HarfBuzz F-8 in `scripts/indic.rs`) is in
`Instructions/SATURATED-REPOS.md § B2`.

## Method note (cost paid this sweep)

GitHub **search** is rate-limited to 30 requests/minute and returns silently-empty results when the
budget is gone — two full keyword batches were lost to this before it was noticed. Cap sweeps at
~20 queries, then `gh api rate_limit --jq .resources.search` before the next batch. The repo-detail
calls (`repos/…`, `pulls/…`) run on the 5000/hr core budget and are cheap by comparison.
