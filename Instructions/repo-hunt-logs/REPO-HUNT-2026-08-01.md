### cloudflare/lol-html — ★2043 — RANK 1

- **URL / stars:** https://github.com/cloudflare/lol-html — ★2043
- **Language:** Rust (pure; deps cssparser, selectors, encoding_rs, memchr, hashbrown — no -sys, no C)
- **Domain:** streaming HTML parser / rewriter with a CSS-selector matching VM
- **Open issues without PRs:** 29 (33 incl. PRs) — below the 100 gate, relaxed
- **License:** BSD-3-Clause (plain 3-clause, no riders) — verified
- **Last commit:** 2026-07-29
- **Test framework:** `tests/` fixture-driven + html5lib-tests suite + inline `#[test]`.
  Behavioural through the public rewriter API. Not mock-heavy.
- **Baseline determinism:** 2 runs identical (182 / 38 / 2 pass, ~0.4s). Clean.
- **Docker:** Pattern A (`olympus-base-rust`), offline-buildable, no system deps
- **Architecture:** `src/parser` (lexer + state machine + tree_builder_simulator) ->
  `src/selectors_vm` (compiled selector VM + match stack) -> `src/rewritable_units` ->
  `src/transform_stream` -> `src/rewriter`. Five real stage boundaries.

**TRAP SEAMS:**
| Pattern | Present | Evidence |
|---|---|---|
| F-1 convergent-architecture wall | **yes (strong)** | the whole point of the repo: `src/transform_stream/dispatcher.rs` emits before the subtree is known. Any selector needing lookahead/lookback has no DOM to consult — the naive DOM-shaped solution is architecturally impossible |
| F-2 bidirectional seam | partial | `tree_builder_simulator/ambiguity_guard.rs:1-207` — implicit tag closing feeds back into the selector match stack |
| F-3 second-axis carve-out | yes | `selectors_vm/error.rs:33-59` — unsupported pseudo-classes AND unsupported combinators are two separate exemption lists |
| F-4 ownership trap | no | arena/index-based, not Rc<RefCell<_>> |
| F-5 transitive pass-through | **yes** | `selectors_vm/ast.rs:317-320` Child vs Descendant combinators — descendant matching is transitive over the open-element stack (`selectors_vm/stack.rs:500`) |
| F-8 named-algorithm override | **yes** | the feature surface is named after CSS Selectors Level 4 but lol-html implements a deliberately narrower streaming subset; the spec's own semantics are the misdirection |
| F-9 cross-stage resolution drop | yes | the parser's state machine already knows sibling/position facts that `selectors_vm` re-derives from its own stack |
| F-10 capability cross-product | **yes** | axis 1 multiplicity: single element vs element-content-handler vs document handler; axis 2 polarity: match-on-start-tag vs match-on-end-tag/content (`OnTagNameExpr` vs `OnAttributesExpr`, ast.rs:41/99) |

**Best Olympus feature types:** (a) sibling-class combinator support in the streaming selector VM —
spans `selectors_vm/{ast,stack,mod}` + the parser's open-element tracking + `rewriter/settings`;
(b) a positional pseudo-class family that needs counts the stream has not seen yet (forces a
buffering/deferral design across dispatcher + selectors_vm); (c) selector-scoped content
capture semantics interacting with the ambiguity guard.

**Estimated complexity:** 300-500 effective LOC across 4-7 files, 3 modules

**Why it matches:** the streaming constraint is the single cleanest F-1 wall found in three hunts —
every "just build the tree" approach is dead by construction, and the failure surfaces as a wrong
match rather than an obvious error. Fixture-driven behavioural tests make the test patch easy to
write. Domain is niche enough that it has not shown up in any prior hunt.

**Risks:** `src/selectors_vm/` is **WARM** — 21 commits in the trailing 12 months, incl.
"make stray end tags and descendant matching linear in depth". Gate 5 COLD-NOT-LIVE must be run
against the exact files before scope-lock. Issue #67 "Adjacent Sibling Combinator" is OPEN with
**no PR** (exclusivity clean at hunt time) but confirms the maintainer knows about the gap —
re-run the canonical-org PR-diff check at scope-lock and again pre-submit. Cloudflare-branded
repos carry some author-obviousness risk; verify the platform sub-count first.

### cloudflare/wirefilter — ★1149 — RANK 2

- **URL / stars:** https://github.com/cloudflare/wirefilter — ★1149
- **Language:** Rust (pure; cidr, memchr, sliceslice, regex-automata, wildcard — no C bindings)
- **Domain:** filter-expression language: lex -> parse -> typecheck against a Scheme -> compile to closures -> execute
- **Open issues without PRs:** 10 (17 incl. PRs) — well below the gate, relaxed
- **License:** MIT — verified
- **Last commit:** 2026-07-30
- **Test framework:** inline `#[test]` across 23 source files + `engine/tests`. Table-driven,
  behavioural through `Scheme`/`FilterParser`/`ExecutionContext`. Not mock-heavy.
- **Baseline determinism:** 2 runs identical (125 / 13 / 23 / 2 pass, ~1.5s). Clean.
- **Docker:** Pattern A (`olympus-base-rust`), offline, no system deps
- **Architecture:** `engine/src/{lex,ast/*,scheme,types,compiler,filter,execution_context}` —
  18k LOC, clear stage boundaries; `ffi/` and `wasm/` are separate crates.

**TRAP SEAMS:**
| Pattern | Present | Evidence |
|---|---|---|
| F-1 convergent-architecture wall | partial | compilation to boxed closures (`compiler.rs:7-60`) means anything needing re-entry into the AST at exec time has to be resolved at compile time |
| F-2 bidirectional seam | yes | `Scheme` is both the declaration registry and the runtime type oracle (`scheme.rs`, 2001 LOC) |
| F-3 second-axis carve-out | yes | LHS types (`lhs_types/{array,map,bytes}`) and RHS types (`rhs_types/*`, 9 modules) are two parallel collections — any new behaviour must land in both |
| F-4 ownership trap | no | value-semantics + lifetimes, no RefCell graph |
| F-5 transitive pass-through | yes | `IndexExpr` chains (`ast/index_expr.rs:337-406`) propagate types transitively through Array/Map nesting |
| F-8 named-algorithm override | **yes** | the language is "Wireshark-like display filters" but deliberately diverges from Wireshark's real semantics — the name is the misdirection |
| F-9 cross-stage resolution drop | **yes** | `ast/index_expr.rs:404-406` resolves element types at lex/typecheck time; `types.rs:715-751` re-resolves the same index at execution time. Two stages, same resolution, different code |
| F-10 capability cross-product | **yes** | axis 1 multiplicity: scalar vs Array vs Map fields; axis 2 polarity: `any(...)` vs `all(...)` quantifiers (`ast/logical_expr.rs:37-196`), crossed with comparison class (ordering / matching / membership) |

**Best Olympus feature types:** (a) a comparison or index capability that must work uniformly
across the scalar x Array x Map by any/all cross-product — spans lex, index_expr, field_expr,
types, compiler, execution_context; (b) a typed-list / set membership surface that has to resolve
identically at typecheck and exec time (aims straight at the F-9 seam).

**Estimated complexity:** 350-550 effective LOC across 5-8 files, 1 crate (single-crate span is
acceptable at the current one-tier Olympus, but weakens the cross-subsystem story)

**Why it matches:** the cleanest F-9 + F-10 pairing in the sweep — the typecheck/execute duplicate
resolution is real and grep-visible, and the quantifier x container-type cross-product gives free
cross-product cells at ~20 test lines each.

**Risks:** `engine/src` is **WARM** — 33 commits in the visible window, and one of the most recent
is "Represent any and all as logical quantifiers", i.e. the maintainer just refactored the exact
quantifier surface F-10 would target. Pick a different axis or a colder file. Single-crate footprint
caps the scope story.
