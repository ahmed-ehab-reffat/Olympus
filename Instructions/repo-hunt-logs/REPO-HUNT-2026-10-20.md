- **Traps (base file:line; I verified 1, 3 and 5 in the clone):**
  1. Clear-history is a time threshold, not a keyed row: `GetCleanTime` (`historymsg/services/hismsgservice.go:806-827`) takes max(group clean, user clean). Moving S's threshold hides T's messages, dropping it resurfaces cleared S messages, and T's own thresholds hide moved S messages. Both must become per-message delete rows first. F-47 / F-28.
  2. The stored body carries its own key: `msg_body` is the marshalled DownMsg with TargetId (`hismsgservice.go:22-147`); readers back-fill only empty fields (`:471-487`). F-59 / F-58.
  3. The conversation store is an authoritative in-memory cache with write-behind persistence (`conversation/services/convercache.go` init: LRU `userconver_cache` plus a 1 s `persistCache`; DB read only on miss). Editing the table directly is invisible or overwritten.
  4. Unread counts live in per-conversation index spaces; `UpsertCovner` only raises the index (`convercache.go:111-115`) and mentions load by index relative to the read index (`:157-200`). Folding must shift T's index and remap every S mention index. F-35 / F-56.
  5. The message service caches each user's counter under its own key (`message/services/converservice.go`, `GetUnreadIndex` increments `UnreadIndex` under a user lock, 10 min LRU). Without invalidation the first post-merge send gets an index `UpsertCovner` ignores: the failure shows in conversations, the cause is in another service. Misdirecting. F-56.
  6. `sub_channel` is part of every key (history, deletes, clean times, conversations, mentions, read infos): default-channel-only merges miss thread history.
  7. Validate before mutate: the member limit is checked inside `AddGroupMembers` (`group/services/groupmemberservice.go` ~:100-110).
- **Gate 1:** base has no merge (`POST /apigateway/groups/merge` 404). The nearest composition (dissolve + add members + `hismsgs/import` per message) mints new ids, drops read counts and receipts, forgets per-user clears and deletes and resets unread counts, all observable through `/hismsgs/query` and `/convers/query`.
