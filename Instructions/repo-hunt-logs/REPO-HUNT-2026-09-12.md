### The capability (shape S-I + S-G, `CAPABILITY-SHAPES.md`)

README, own words:

> Because tile-join just copies the geometries to the new .mbtiles without processing them (except
> to rescale the extents if necessary), **it doesn't have any of tippecanoe's recourses if the new
> tiles are bigger than the 500K tile limit. If a tile is too big and you haven't specified `-pk`,
> it is just left out of the new tileset.**

Give `tile-join` the recourses `tippecanoe` has: when a merged tile exceeds the size budget, reduce
it — rank and drop features, coalesce, reduce detail — instead of silently omitting the tile.

**Gate 1 / Gate 6 — BEHAVIOURAL F2P GAP REPRODUCED ON BASE, in the platform image:**

```
in : [(0, 0, 0, 1001495)]                 # one tileset, one tile, 1,001,495 bytes (built with -pk)
=== BASE tile-join (no -pk):
0/0/0  Tile 0/0/0 size is 1001495, >500000. Skipping this tile.
exit=0
out: []                                    # the output tileset is EMPTY
meta: {"vector_layers":[{"id":"big", ... "minzoom":0,"maxzoom":0,"fields":{...}}]}
```

The output advertises a layer, its fields and its zoom range in `metadata`, and contains no tiles.
Exit status is 0. That single probe shows the gap AND the first interdependence.

The whole recourse is `tile-join.cpp:884`:

```cpp
if (!pk && compressed.size() > 500000) {
        fprintf(stderr, "Tile %lld/%lld/%lld size is %lld, >500000. Skipping this tile.\n", ...);
} else {
        a->outputs.insert(...);
}
```

### Stage 3b — absorption: NAME THE MACHINERY THE REPO LACKS

tippecanoe's ladder (`tile.cpp:2740-3010`, plus `choose_mingap` / `choose_minextent` /
`choose_minattribute` / `choose_mindrop_sequence`, ~300 effective lines) runs over
`std::vector<serial_feature>`, and every quantity it ranks by — `index`, `gap`, `extent`,
`drop_sequence`, `feature_minzoom` — is **filled in by the serial pipeline before tiling**.
`tile-join` has none of it: it merges already-encoded `mvt_layer`/`mvt_feature` objects in tile
coordinates, with no index order, no extent, no drop sequence.

The one thing that looks like absorption is `overzoom()`'s `feature_limit` (`clip.cpp:1613,1686`) —
but it is a naive **count** cap that keeps the first N features per layer in input order, not a
density-ranked, size-targeted reduction. An implementation that reaches for it fails any test that
states the surviving features must stay evenly distributed.

**Missing machinery, named:** a density-ranked, size-targeted feature-dropping search over
already-encoded tile features — world-index reconstruction from tile-space coordinates per layer
extent, per-feature extent on tile geometry, a convergent drop/re-encode/re-measure ladder,
attribute accumulation folded into survivors, and tileset-statistics reconciliation.

**Sketched diff against the sibling:** world index + gap 70-90 · extent 40-60 · attribute-value
extraction over `mvt_value` 40 · ladder + convergence guard 130 · shared `choose_*` helpers 70 ·
accumulation on drop 60 · layermap/tilestats reconciliation 50 · option plumbing + usage + README/man
70. **~530-570 raw, ~350-430 effective (Counter 2)** against a 200 floor. Above the floor with buffer;
a thinnest-end-to-end spike is still owed before scope-lock (`REPO-HUNT-2026-09-10-D` law).

### TRAP SEAMS (`failure-patterns.md`)

| Pattern | Present | Evidence |
|---|---|---|
| **F-9 cross-stage resolution drop** | **yes** | `append_tile` (tile-join.cpp:101-390) fills `layermap`/tilestats — feature counts, per-layer min/max zoom, attribute histograms — **before** `join_worker` decides whether the tile fits. | **F-10 cross-product** | **yes** | axis 1 = recourse {drop-densest, drop-smallest, drop-by-attribute, coalesce, reduce detail}; axis 2 = geometry kind {point, line, polygon}; axis 3 = output {mbtiles, dirtiles, pmtiles}; axis 4 = joined vs pass-through features (`-c` CSV join, `-i/--if-matched`, `-j` filter) |
| F-4 ownership | n/a | C++, `mvt_tile` copies |

**Phase-3 death-class guard:** one kernel (rank-and-drop-to-budget) feeds several surfaces — the
three tileset writers, the layermap/tilestats accounting, the `strategy` records, attribute
accumulation, and the multithreaded `join_worker` dispatch. A fix that satisfies the writers alone
regresses the metadata; a fix that drops without accumulating regresses `--accumulate-attribute`.
Not solvable by a standalone file with minimal wiring.
