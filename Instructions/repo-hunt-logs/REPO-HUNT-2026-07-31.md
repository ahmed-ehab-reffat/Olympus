### rust-minidump/rust-minidump — ★505 — RANK 1

- **URL / stars:** https://github.com/rust-minidump/rust-minidump — ★505
- **Language:** Rust (pure — zero `-sys` crates, zero vendored C, verified across all 7 member manifests)
- **Domain:** crash-dump parsing + stack unwinding + symbolication
- **Open issues without PRs:** 77 (total open issues 77, open PRs 20 — 11 of those dependabot)
- **License:** MIT — read `LICENSE` plus all 7 per-crate `LICENSE` files, every one MIT
- **Last commit:** 2026-07-27 (15 commits/90d repo-wide)
- **Test framework:** cargo, per-arch `*_unittest.rs` + integration tests. `minidump-synth` is a
  **synthetic minidump builder crate** — behavioural tests construct real dumps through the public
  API, no mocks, no external fixtures. This is the ideal test-patch substrate.
- **Baseline determinism:** 266 tests, **3 runs identical**, ~6s total, fully offline. Clean.
- **Docker:** Pattern A (`olympus-base-rust`) — plain build, no system deps, offline-safe
- **Architecture:** 7 crates — `minidump` (10.6k) / `minidump-common` (9.3k) / `minidump-unwind`
  (9.4k) / `breakpad-symbols` (6.4k) / `minidump-processor` (5.1k) / `minidump-synth` (2.3k) /
  `minidump-stackwalk`. 44k Rust LOC. Real cross-crate boundaries.

**TRAP SEAMS:**
| Pattern | Present | Evidence |
|---|---|---|
| F-1 convergent-architecture wall | **yes (strong)** | `minidump-unwind/src/x86.rs:363` `get_caller_frame` is a literal degrading cascade: `get_caller_by_cfi` (:22) -> `get_caller_by_frame_pointer` (:89) -> `get_caller_by_scan` (:168). Each fallback **destroys structure the next stage cannot recover** — lib.rs:54 says so outright ("stack scanning, it can wind up with dubious frames") |
| F-2 bidirectional seam | **yes** | `x86.rs:207` — the scan stage *reads the callee frame's* `FrameTrust`, so a trust level decided by an earlier frame changes how a later frame is recovered. Fixing one stage's trust assignment perturbs the other stages' behaviour |
| F-3 second-axis carve-out | yes | `FrameTrust` (`lib.rs:61-95`) is a 5-level lattice (Context / CallFrameInfo / CfiScan / FramePointer / Scan) crossed with per-architecture unwinders (x86 / amd64 / arm / arm64 / mips) — an exemption on one axis has to hold on the other |
| F-4 ownership trap | no | only 2 `Rc`/`RefCell` sites |
| F-5 transitive pass-through | **yes** | inline frames, `lib.rs:128-253` — `StackFrame::inlines` are "ordered inside to outside" and cover a frame address; an inlined function is a pass-through node in the frame chain |
| F-8 named-algorithm override | **yes (high value)** | The whole crate is a deliberate re-implementation of Google **Breakpad**'s stackwalker and its symbol format. The repo's own docs flag places it knowingly diverges. The famous reference is what the agent will assume; the repo's real behaviour is the discriminator |

**Best Olympus theses (each names its span + seam):**
1. **Trust-aware unwind repair across `minidump-unwind` + `minidump-processor` + `breakpad-symbols`.**
   Exploits F-1 + F-2: a correction in the CFI stage changes what the scan stage is allowed to
   accept, and the processor's frame-list post-processing must stay consistent. Naturally 3+ crates.
2. **Inline-frame reconstruction through the trust cascade** (F-5 + F-1): inline frames recovered
   from symbols must survive a frame whose parent was recovered by scanning. The pass-through node
   is the trap; the fix is not local to either crate.
3. **A second architecture's unwinder brought to parity on the same trust lattice** (F-3): forces
   the same rule to hold on both the trust axis and the arch axis, and `minidump-synth` makes both
   testable deterministically.

**Estimated complexity:** 300-550 effective LOC across 4-8 files, 3-4 crates
**Why it matches:** maximally obscure to problem authors (crash forensics — nothing like the
VM/SQL/config set that saturated), genuinely cold in the target subsystem (`minidump-unwind` 7
commits / 12 months, `minidump-processor` 13), globally coupled by construction, and the cleanest
feasibility profile of anything found: deterministic, offline, fast, pure Rust, MIT.
**Risks:** ★505 sits right on the 500 floor — re-verify before submit. Open PR **#1162
"add configurable UnwindStrategy to SymbolProvider"** and **#1164 "gradual off-by-one bitflip
confidence detractor"** both touch the unwind path — pull both diffs at scope-lock (Gate 7b).
`reqwest` appears as a dep for the HTTP symbol supplier; keep it out of the test path (it already is).

### typst/hayagriva — ★689 — RANK 2

- **URL / stars:** https://github.com/typst/hayagriva — ★689
- **Language:** Rust (pure, no C deps)
- **Domain:** bibliography management + CSL (Citation Style Language) rendering
- **Open issues without PRs:** 155 — inside the window
- **License:** MIT OR Apache-2.0 (dual, both files present)
- **Last commit:** 2026-07-15 (34 commits/90d; **`src/csl` only 27 commits in 12 months** — cold target inside a live repo)
- **Test framework:** cargo. `tests/citeproc.rs` runs the **official citeproc conformance suite**
  against `tests/citeproc-pass.txt`, a 517-line allowlist of currently-passing cases. Plus
  `tests/local/` fixture tests that need no network.
- **Baseline determinism:** 64 tests, **3 runs identical**, 0.25s. Clean.
- **Docker:** Pattern A — **caveat:** `tests/citeproc.rs` calls `ensure_repo()` to git-clone the
  upstream CSL test repo at test time. Base mode must be scoped to the unit + `tests/local` tests
  with a documented reason (`TESTS.md` allows this).
- **Architecture:** single crate, 18.5k LOC; `src/csl` (rendering / taxonomy / sort / elem) is the
  deep part, `src/types`, `src/lang`, `src/interop` around it.

**TRAP SEAMS:**
| Pattern | Present | Evidence |
|---|---|---|
| F-1 convergent-architecture wall | yes | speculative rendering: `cite_props.speculative` is built (`csl/mod.rs:188`) before disambiguation runs, so the render that decides disambiguation is itself provisional |
| F-2 bidirectional seam | **yes (strongest found)** | Disambiguation is globally coupled *by definition* — whether cite A needs disambiguating depends on every other cite, and disambiguating A can create a fresh collision with B. `csl/mod.rs:250-283` is a 3-stage cascade (2a names -> 2b `cs:choose` -> 2c year-suffix) with per-entry `DisambiguateState` fed back through `rerender` |
| F-3 second-axis carve-out | yes | `DisambiguationRule` (AllNames / ByCite / AllNamesWithInitials / PrimaryName / PrimaryNameWithInitials) crossed with `et_al_min` truncation — `csl/mod.rs:771-798` |
| F-4 ownership trap | no | 5 `Rc`/`RefCell` sites |
| F-5 transitive pass-through | partial | `names.rs:96` carries a live `TODO: Use for disambiguation of identical names` — an unimplemented pass-through case |
| F-8 named-algorithm override | yes | CSL 1.0.2 has a reference implementation (citeproc-js) the agent will assume; hayagriva diverges in documented places |

**Best Olympus theses:**
1. **Close a cluster of citeproc `disambiguate_*` conformance failures** (38 of the 517 allowlisted
   are disambiguate cases; the suite has more that are not listed). Spans `csl/mod.rs` +
   `csl/rendering/names.rs` + `csl/taxonomy.rs`. Pure F-2: any local fix re-collides elsewhere.
2. **Name-form disambiguation completion** — the `names.rs:96` TODO, extended to interact with
   year-suffix assignment and sort order (`csl/sort.rs`), so the fix must reach a fixed point.

**Estimated complexity:** 250-450 effective LOC across 3-6 files, 1 crate (single-crate span is the
weakness — needs a deliberate second axis to clear the file-count and scope bars)
**Why it matches:** the citeproc allowlist is *documented, honest incompleteness* — exactly what the
`lesson_repo_selection_incompleteness_over_depth` memory says to hunt for. Bibliography processing
is far off the author-obvious path. The disambiguation algorithm stays hard even when fully
specified, which is the property `TOO-EASY.md` demands.
**Risks:** (a) **PR #250 "Fix unnecessary disambiguation around ibids"** is open and lands in the
disambiguation path — pull the diff before scope-locking anything disambiguation-shaped;
(b) CSL is a published spec with a reference implementation, so the saturated-reference-port class
is a live concern — pick a divergence, not a transcription; (c) single crate limits cross-subsystem
span; (d) the network-dependent conformance test needs base-mode scoping.

  `lir_tests/`, `optimization_testcases/`) + 153 in-source `#[test]`. Behavioural, no mocks.
- **Baseline determinism:** **NOT VERIFIED** — could not build (LLVM absent, and disk is at 97%).
- **Docker:** **the blocker.** `default = ["llvm", "wasm_opt", "language_server", "soroban"]`;

  kill-list "vendored C toolchain" signal.
- **Architecture:** 117k LOC — `solang-parser` -> `src/sema` (26 files: types, mutability, symtable,
  yul, solana_accounts) -> `src/codegen` (cfg + optimize + per-target) -> `src/lir` -> `src/emit`
  (polkadot / solana / soroban) -> `src/linker`. The richest F-1 pipeline found by a wide margin.

**Verdict:** highest seam value in the sweep, gated behind one question. **Before any authoring,
prove that `cargo test --no-default-features` builds and that `tests/lir.rs`, `tests/builtins.rs`
and `tests/borsh_encoding.rs` (0 LLVM references each) run green.** If that works, solang is a
first-rank target: sema-to-codegen picks never touch `emit/` and the multi-backend structure makes
cross-subsystem scope trivial to reach. If it does not, drop solang — do not try to install LLVM in
the image.
**Other risks:** 53 open PRs is the highest of any finalist (exclusivity pressure); Solidity itself
is a well-known spec, so target solang's own target-divergence rather than Solidity semantics.
