### The capability — resolve the cost scale once, and make it survive every representation

`Geometry` carries a `scale_cost` option whose string modes (`"mean"`, `"max_cost"`, `"median"`,
`"max_norm"`, `"max_bound"`) are **re-implemented independently in every subclass**, each supporting
a different subset and raising `NotImplementedError` on the rest. Measured on the source:

- `Geometry.median_cost_matrix` materialises the whole cost matrix, while `mean_cost_matrix` and
  `std_cost_matrix` are deliberately written through `apply_cost` / `apply_square_cost` so they stay
  valid for low-rank and online geometries. `Grid` returns `NoReturn` for the median.
- `PointCloud.inv_scale_cost` raises for `"median"` in online mode, and for `"max_bound"` when the
  cost is neither squared Euclidean nor negative dot product.
- `LRCGeometry` applies the scale as `sqrt(scale)` on **both** factors and separately on the `bias`.
- `Geometry.inv_scale_cost` reads `self._cost_matrix`, so a kernel-defined geometry with a
  non-float `scale_cost` fails outright.
- `Geometry.subset` is implemented on the materialised cost/kernel; only `PointCloud` overrides it.
- `tools/sinkhorn_divergence` builds three geometries `(x,y)`, `(x,x)`, `(y,y)` through
  `prepare_divergences` and has a `share_epsilon` flag that copies one epsilon into all of them —
  **but no equivalent for the scale**, so each of the three terms normalises its cost by its own
  statistic and the debiasing terms are no longer in the same units. `segment_sinkhorn` has the same
  problem per segment.

The capability is to resolve the scale **once**, from a statistic computed without materialising the
cost, and transfer it into geometries of different classes so that every representation agrees —
including the online path, the low-rank factorisation with its bias, and the exponential rule a
kernel-defined geometry needs.

**Machinery the repo lacks (Stage 3b):** there is no geometry-agnostic statistic estimator — the
median has no non-materialising implementation anywhere, so an online median over an implicit n x m
matrix is a real algorithm to write, not a call-through; there is no scale-transfer that preserves a
factorised representation (`set_scale_cost` re-flattens the tree and cannot carry a numeric scale
into `LRCGeometry`'s two factors plus bias); and `copy_epsilon` is not a template for it, because it
copies a single float while the scale must be recomputed per representation. Sketch: statistic
estimator + online median ~120 - scale transfer across classes ~60 - LR factor/bias preservation ~30
- kernel exponential rule ~40 - divergence and segment wiring ~70 - validation and canonical edge
rules ~40 -> **~360 raw, ~300 effective, 7-9 files across 3 packages.**

### ott-jax/ott — the cost-scale lane is MACHINERY-ABSORBED

The hunt's thesis was: resolve one cost scale from a statistic computed without materialising the
cost, and transfer it across geometry classes and across the Sinkhorn divergence's three terms. The
seams are all real and were confirmed at file:line. The capability is not.

- **The statistic layer is already generic.** `Geometry.mean_cost_matrix` and `std_cost_matrix` are
  deliberately written through `apply_cost` / `apply_square_cost` precisely so they work for low-rank
  and online geometries (`geometry.py:112-135`). For the separable `Grid`, each per-dimension slice is
  an ordinary `PointCloud` (`grid.py:114`), so the exact decompositions are one-liners: mean = sum of
  per-dimension means, max = sum of per-dimension maxima, variance = sum of per-dimension variances.
  The new "algorithm" is about five lines.
- **The sharing layer is ~10 lines.** `sinkhorn_divergence.py:237` already has `share_epsilon` calling
  `copy_epsilon`; a `share_scale_cost` twin resolves one scalar and calls `set_scale_cost` three times.
- **The one genuinely new algorithm is not behaviourally testable.** A non-materialising MEDIAN over
  an implicit n x m cost matrix is real work, but on every geometry except `Grid` a materialising
  implementation is *correct* and only wasteful, so no fair test can separate the two. That is the
  L44 unbounded-promise class: a performance claim masquerading as a contract.
- **Honest sizing of the fullest defensible scope** (Grid statistics + scale threading through
  `geometries`/LR/epsilon + `std` mode + divergence and segment sharing + carve-outs): ~270 raw,
  **~200-220 effective — at the floor with no buffer.** The doctrine's design target is 300+.

**What was genuinely good here, and should be reused if the repo is ever re-picked:** `Grid` is the
one geometry where "cannot materialise" is enforced by an exception (`grid.py:322`, `grid.py:329`),
not by memory pressure, so it turns a performance claim into a testable one. And `Grid.geometries`
drops `scale_cost` when it builds the per-dimension point clouds, so the obvious one-line fix
(forward `scale_cost` to each slice) is WRONG — each dimension would normalise by its own statistic
instead of the total — and it is invisible on the 1-D and symmetric grids an agent self-tests with
(P3 self-test-shadow). That is a strong trap. It is attached to a capability too small to carry it.

**Everything else in ott's cold half is a derivative magnet:** partial OT (#614), bottleneck
assignment (#648), Bregman/Fréchet k-means (`k_means.py:393` asserts squared Euclidean), convolutional
grid barycenters, structured multi-marginal Sinkhorn (`experimental/mmsinkhorn.py:157` materialises the
full k-tensor). Every one is named by the OT literature and several are shipped by POT.

**One latent bug worth recording:** `TICost.barycenter` (`costs.py:262`) returns the plain arithmetic
average for EVERY translation-invariant cost, which is correct only for squared Euclidean. The
weighted Frechet mean under `PNormP`/`SqPNorm` is not the arithmetic mean. It is currently unreachable
from `k_means` (which asserts squared Euclidean) but IS reached by the free-support barycenter. A
future pick could be built on it, but "k-means under a general cost" is the textbook-name magnet
above, so it needs a non-nameable framing first.

### The transferable law

**Cold + well-factored is exactly the profile of a repo whose remaining capabilities are absorbed.**
A library is cold BECAUSE its abstractions already cover its domain; the hunt's own ranking signals
(cold directories, zero open PRs, clean dedup) select for that. The hunt ranks AVAILABILITY; the
absorption sketch measures SIZE; and they are anti-correlated. **Sketch the diff in effective LOC
against the nearest existing sibling during the HUNT, not at authoring**, for the RANK 1 candidate's
named lane — it is the same 10 minutes either way and it was the deciding number for both repos here.
