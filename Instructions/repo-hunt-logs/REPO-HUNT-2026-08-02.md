  Offline-safe, no system deps.

**STAGE 2b DERIVATIVE-RISK: LOW — the strongest score of anything hunted so far.**

Every open issue in the tracker is unnameable outside the repo: "Completion percentage not precise
enough with relatively large objects", "Multiple relocations at a single instruction are not
supported", "Ability to check if matching symbols are in the wrong order", "ARM mapping symbols
interpreted incorrectly when using Combine text sections". There is no external standard that
defines objdiff's symbol-matching, its diff scoring, or its mapping model, so two authors cannot
converge on the same pick the way three of them converged on "add `:is()` to lol-html". The dedup
one-liner for any pick here necessarily contains repo-specific nouns.

**TRAP SEAMS (failure-patterns.md):**
| Pattern | Present | Evidence |
|---|---|---|
| F-1 convergent-architecture wall | plausible, unconfirmed | scoring is computed during the diff walk; anything needing a global view of the match set may not be expressible in the natural single-pass shape. Cannot confirm before a batch (F-1 never can) |
| F-2 bidirectional seam | **yes** | symbol matching is a two-sided assignment between left and right objects; `DiffSide` (`diff/mod.rs:811`) and `MappingSymbolDiff` (`:53`) make the polarity explicit, and a match on one side constrains the other |
| F-3 second-axis carve-out | **yes (strong)** | `diff_code` (`diff/code.rs:58`) and `diff_data_section` / `diff_data_symbol` (`diff/data.rs:230,363`) are two parallel families. Any rule stated over "sections" or "symbols" must land in both, and the data side has its own third axis in `DataRelocationDiff` (`diff/mod.rs:91`) |
| F-4 ownership trap | no | arena/index based |
| F-5 transitive pass-through | plausible | relocation targets chain through symbols to other sections |
| F-8 named-algorithm override | **available but deliberately unused** | the diff itself rides the `similar` crate (Myers). Per the Stage 2b note, F-8 is safe only as misdirection over an invented divergence, never as the scope |
| F-9 cross-stage resolution drop | **yes** | `obj/read.rs` resolves symbols and relocations at parse time; `diff/display.rs` re-resolves for rendering. Two stages, same resolution, different code — the exact precondition |
| F-10 capability cross-product | **yes (strong)** | axis 1 polarity: `DiffSide` left vs right; axis 2 kind: code vs data section; axis 3 multiplicity: one symbol vs a mapping set. Off-diagonal cells are cheap and unlikely to be built |

**Best feature theses (invent the scope; the issues only prove the domain is alive):**
(a) a scoring/matching property that must hold across both section families and both sides at once
— spans `obj/read`, `diff/code`, `diff/data`, `diff/mod`, and every arch backend that supplies
relocations; (b) a relocation-resolution capability where the parse stage and the display stage
must agree (straight at the F-9 seam); (c) a symbol-mapping invariant that survives ordering
differences between the two objects.

**Estimated complexity:** 300-500 effective LOC across 4-7 files, 3 modules + arch backends.

**Risks:** ★504 is one bad week from the 500 floor. Snapshot tests (`tests/snapshots/`) mean a
behaviour change touches fixture files — manageable but it inflates the test diff. Six arch
backends invite repetitive breadth, which the human LOC counter amortises to the pattern, so scope
must go DEEP (one hard property) not WIDE (the same rule six times).

**GATE RESULTS (run 2026-08-02, after the dossier above):**

*Testability — SOLVED, better than expected.* `Object` derives `Default` with an `ArchDummy`
backend and every field is `pub`, so objects can be built programmatically in tests — no binary
blobs in test.patch. Verified with a live probe against `diff_objs`. For anything needing a real
architecture, the repo ALREADY ships paired fixtures (`tests/data/ppc/CDamageVulnerability_base.o`
+ `_target.o`, `mips/code_be.o` + `code_le.o`) and `tests/arch_ppc.rs:75` already runs a full
`diff_objs` over the pair, so real end-to-end tests also need no new binaries.

*Gate 1 BEHAVIORAL-F2P-GAP — confirmed on the symbol-matching surface.* Probe result: a symbol that
is byte-identical but RENAMED gets `target=None, match=None`, while reordering (100%) and content
changes (50%) are both handled. Real observable gap.

*Gate 5 COLD-NOT-LIVE — the symbol-matching pick is DEAD.* Automatic symbol pairing is an active
maintainer workstream: PR #247 "Improve automatic symbol pairing for nameless literals" and #278
"Adjust symbol name matching logic for GCC" both MERGED, issue #297 "sort unmapped base symbols by
matching percentage" OPEN, and **PR #385 is OPEN with +103/-5 in `objdiff-core/src/diff/mod.rs`** —
the exact file holding `matching_symbols` and `diff_objs`. Whether or not that trips the
exclusivity AND-test (it adds a display-ordering field, not the matching algorithm), a live
workstream in the target file fails Gate 5 on its own. Do not pick symbol matching here.

Two conclusions. First, **PR #358 IS the content-based unmatched-symbol matching capability** this
hunt was about to invent — publicly solved, and invisible to the keyword searches ("symbol
matching", "rename", "fuzzy") run earlier, because its title shares no keyword with the feature.
Second, **there is no cold file left in `objdiff-core`** — #381 alone covers all three diff files.
The `diff/code.rs` zone is not cold after all, and the earlier per-file commit-count map was
misleading because it measures merged history, not the open queue.

Compounding it: `diff/code.rs` also turned out to be untestable with precise synthetic scenarios,
because `ArchPpc::new` / `ArchMips::new` both require a parsed `object::File`, so a real
instruction decoder cannot be constructed programmatically. Code-diff tests are limited to the two
existing fixture pairs, or would need new binary blobs in test.patch.

**Verdict: objdiff is DEAD for authoring until the PR queue drains.** Recorded in
`SATURATED-REPOS.md`. Everything else about it was excellent (Stage 2b LOW, deterministic, trivial
programmatic tests via `Object: Default`) — the blocker is exclusivity, not quality.

*Process lesson, now a gate (`olympus-hunt § Stage 2c`):* enumerate every open PR's FILE LIST.
Keyword search over PR titles is not sufficient and has now missed a publicly-solved twin twice.
