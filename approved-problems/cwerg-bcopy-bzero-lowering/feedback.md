## Round 4 (2026-09-10) — second Solution Quality FAIL, all three issues real
1. **Unsigned constants >= 2^63 diverged between the backends.** `ConstValueAsInt` returned
   `ConstValueU` through an `int64_t`, so a U64 constant at or above 2^63 came back negative in C++ and
   the constant path chose `_bulk_down`; Python compared a positive arbitrary-precision int and chose
   `_bulk_up`. That is both a wrong direction AND a parity break. Replaced it with three flavor-aware
   helpers -- `ConstIsZeroValue`, `ConstIsNegativeValue` (signed flavor AND `ConstValueACS() < 0`), and
   `ConstWithKind` (re-creates the counter constant with `ConstNewU` for unsigned kinds, `ConstNewACS`
   for signed) -- so an unsigned value is never routed through a signed type. Python now states the same
   rule explicitly (`flavor() is DK_FLAVOR_S and value < 0`); its behaviour was already right, but the
   two now read identically, which is the point of the parity clause.
2. **C backend broke at the S64/U64 extrema.** Induction was always `int64_t`, and the downward loop
   `for (i = -1; i >= n; --i)` decrements past INT64_MIN when n is the smallest S64. Now the induction
   type follows the length's flavor (`uint64_t` for unsigned, so an unsigned length is never compared
   as signed), the length is cast to that type at the use site, and the downward loop is restructured to
   `for (k = 0; k > n; --k) dst[k - 1] = ...` which stops exactly at n and never steps below it. Verified
   the emitted C compiles warning-free and still reproduces the goldens byte for byte.
   - Left `RegOrNum` alone deliberately: its `{value}LL` formatting is pre-existing repo code on every
     instruction's constant operands, so changing it would be a drive-by touching all C output. The cast
     at the use site fixes the value domain for the bulk path without that blast radius.
3. **Generated opcode reference did not list the new opcodes.** Regenerating `IR/Docs/opcodes.md`
   wholesale produces ~25 lines of UNRELATED churn -- the checked-in file is already stale against its
   own generator (trailing whitespace on ~20 rows, plus `.reg names [NAME_LIST]` -> `[NAME]`). Inserted
   only the two overview rows and the two detail sections the generator emits for bcopy/bzero, at the
   generator's own positions (after `gettp`, before Directives). Result is 16 insertions, 0 deletions.

1. **High-bit unsigned at NATIVE width (U32/U64) — physically untestable, and the checker says so.**
