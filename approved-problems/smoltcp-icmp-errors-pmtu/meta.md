# Deliver ICMP errors to sockets and learn the path MTU

Nothing in this stack reacts to an incoming ICMP error, so a connection into a black hole learns nothing and a segment too large for the path is retransmitted at the same size forever. Make it act on them.

An ICMP error quotes the packet that provoked it, and is only guaranteed to carry that packet's IP header plus eight bytes, which is enough for the source and destination ports and, for TCP, the sequence number. Use that to find the socket that sent the quoted packet and report the error to it. Add `smoltcp::socket::IcmpError`, deriving `Debug`, `Clone`, `Copy`, `PartialEq` and `Eq`, with the variants `NetUnreachable`, `HostUnreachable`, `ProtoUnreachable`, `PortUnreachable`, `SrcRouteFailed`, `Prohibited`, `TimeExceeded`, `ParamProblem` and `PacketTooBig { mtu: usize }`, plus `is_hard(&self) -> bool`, true for the reasons that say the destination cannot be reached and false for the rest. The `tcp`, `udp` and `raw` sockets each gain `take_error(&mut self) -> Option<IcmpError>`, which returns the error last reported about them and clears it.

An error is acted on only when the quoted packet was sent from one of this interface's own addresses, when its addresses and ports match a socket, and, for TCP, when the quoted sequence number is one that socket still has outstanding. A raw socket bound to the version and protocol of the quoted packet is told as well. A hard error that reaches a TCP socket still opening its connection closes it. In every other state, and for every soft error, the connection is left alone and the error is only recorded.

An ICMPv4 "fragmentation required" carries a next hop MTU in the second half of its header, and an ICMPv6 "packet too big" carries one of its own. Both record a path MTU for the destination of the quoted packet, whether or not a socket matches it. A recorded MTU is at most the interface MTU, at least 576 for IPv4 and 1280 for IPv6, and never above what already applied. A report of zero, which old routers send, means the next size down the list of MTUs links commonly have: 65535, 32000, 17914, 8166, 4352, 2002, 1492, 1006, 508, 296, 68. A report holds for ten minutes, and once it is exactly that old the next size up that list is tried, then the one above it ten minutes later, until the destination is back at the interface MTU. `Interface::pmtu(dst)`, taking anything that converts into an `IpAddress`, returns the size in effect for a destination, and `Interface::flush_pmtu()` forgets every entry.

Everything the stack sends to a destination is then sized by that destination's path MTU rather than by the interface MTU. That covers TCP segments, including the retransmission of the segment an error was about, and IPv4 fragmentation. The maximum segment size advertised in a SYN still comes from the interface MTU.
