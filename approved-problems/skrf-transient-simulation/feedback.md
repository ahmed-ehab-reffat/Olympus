## Design decisions (assumptions logged as made)

1. Autonomous one-shot mode; the repo was auto-discovered under the "brand new repo, brand new hard
   feature" standing preference.
2. The engine deliberately does NOT reuse `Network.impulse_response`. That helper `fftshift`s its
   output (centred, not causal) and windows by default, which is right for gating and wrong for
   driving a source through a channel. Leaving it untouched keeps the existing behaviour intact and
   turns "reuse the obvious helper" into trap 2.
3. `Circuit.transient` requires a grid that already starts at 0 Hz rather than extrapolating, because
   `extrapolate_to_dc` is a `Network` method and a circuit has no equivalent. The asymmetry is
   stated outright in the description.
4. Source and load impedances are restricted to real, positive, frequency independent values. That
   keeps the wave definitions unambiguous and is stated.
5. meta.md is 494 words against the "hard cap 500" in CLAUDE.md. Every sentence carries a tested
   rule; the approved `pyparsing-parse-enumeration` meta is longer still.
6. Effective LOC is 362 (hook `human-effective`), 684 raw, 4 files. That clears the 2026-07 sprint
   floor (>= 250 effective, >= 2 files) with 45 percent margin and clears the 500 raw "Good" target,
   but it is under the older 430 design target the hook still prints. Three orthogonal surfaces were
   added for real (network terminations that re-reflect to all orders, eye statistics, TDR impedance
   profile) rather than padding; a fourth was not invented purely to chase the number.

## Bugs the mutation and probe work found in the reference

- `Circuit.transient` originally multiplied the circuit's global S by the spectrum of the source,
  which is a circular convolution. A step held for the whole record is indistinguishable from DC
  under it, so a delay line showed no delay at all. Rewritten to build the impulse matrix and
  linear-convolve, matching the network path.
- `overshoot` floored its result at zero. The maximum of a record is always at least its last
  sample, so the floor could never fire; it was dead defensive code and was removed.
- `Eye.width` walked outwards from the centre column to find a contiguous open run. No reachable
  configuration produced a non-contiguous open set, so the walk was unreachable; `width` now counts
  the open columns, which is what the description states.
- The eye start index used `ceil(delay / dt)`, which lands one sample late when `delay` is exactly a
  grid point in binary. It now uses the actual time vector.

## Fairness / FP work (the "close the FP" pass)

- Every meta clause maps to at least one test, and every test assertion traces back to a clause. Two
  clauses were tightened after the audit: the centre column of an eye is defined explicitly (half the
  column count rounded down), and `width` is stated as the total open time rather than a span.
- One test (`test_circuit_voltages_are_unchanged_by_the_transient_support`) passed on base, because it
  only guarded the existing `Circuit.voltages`. It was rewritten to cross check the settled transient
  node voltages against `Circuit.voltages` at DC, so it now exercises both APIs and fails on base.
- The eye-delay test was moved off an exact grid point so that both `searchsorted` and a
  `ceil(delay/dt)` implementation of "the first sample at or after delay" agree; the test no longer
  turns on a floating point technicality.
- Fixed-point audit: the transformations the description names (renormalize, extrapolate to DC, clip
  a ramp) are all idempotent, so no test input is a fixed point that hides a doubled application.
- 14 mutations of the reference were run against the suite; all 12 that remain applicable are killed,
  each by the test written for it. The two that no longer apply targeted the dead code listed above,
  which was deleted rather than kept.

## Round 16 - Test Fairness FAIL (1 of 192) - the reference contradicted its own rule

`test_threshold_time_reports_the_start_when_the_level_already_holds` asserted that a waveform starting
at 0.5 V and falling to zero reports time zero for the level 0.6 V. That waveform never reaches 0.6,
and the description says a crossing that never happens is not a number. The test was wrong AND so was
the reference behind it.

Root cause: `threshold_time` inferred a direction from the endpoints (`rising = v[-1] >= v[0]`) and
then took the first sample on the satisfying side. For a falling record every sample is already below
a level above the start, so it returned `t[0]` instead of nan. The heuristic, not the test, was the
defect.

Replaced with a direction-agnostic true-crossing search: find the first adjacent pair whose offsets
from the level have opposite signs (or touch zero) and interpolate between them, otherwise nan. This
is literally "the first crossing ... not a number when it never happens", handles rising, falling and
exact-hit records with no direction inference, and is shorter than what it replaced. The test now
asserts nan.

Two battery updates followed. M7 went PATCH-MISS because its target line was inside the rewritten
function - a reminder that a mutation reporting PATCH-MISS means the harness is stale, never that the
code is fine - and was retargeted. A new M15 was added for exactly the defect class the reviewer
caught: "no crossing required, report the start instead of nan". It is killed by both nan tests.
Battery is now 13 of 13.

One flakiness run wrote no JUnit file (a transient IO failure while the shared disk was under
pressure). Re-ran all three from scratch rather than reporting a two-of-three result: identical every
time.
