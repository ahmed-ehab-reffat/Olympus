# Add validity interval histories to Table

Add a family of history methods to `Table`, plus a `Coverage` aggregation, so tables describing how something looked between two moments can be built, tidied, questioned and joined inside agate. Tests run from the repo root with `python -m pytest tests/`.

A history table has one or more key columns, a start column, an end column and any number of value columns. An interval runs from its start up to but not including its end, and an end of null means it has not finished yet. Starts and ends must both be `Date` columns or both `DateTime` columns, and anything else raises a `DataTypeError`. A null start, or an end at or before its own start, raises a `ValueError`, as does giving a method a name for a column it adds that the table already uses.

Every key argument is a column name, a column index, or a sequence of either, and the two interval columns are named by `start_column_name` and `end_column_name`, which default to `valid_from` and `valid_to`. Any instant handed to one of these methods is cast with the data type of the interval columns, so strings work everywhere. Value columns are the ones that are neither key nor interval columns, and two nulls count as equal values. Unless a method says otherwise, keys come out in the order they first appear and rows within a key come out in order of interval start. `coalesce_history`, `flatten_history`, `split_history` and `clip_history` hand back the same columns they were given, in the same order.

`to_history(key, effective)` turns dated observations into intervals. Its columns are the key columns, then the two interval columns, then the value columns in their original order, and the `effective` column is dropped. It must be a `Date` or `DateTime` column, or a `DataTypeError` follows, and a null in it raises a `ValueError`. The observations of a key are read in order of `effective`, and where two of them share an instant the one further down the input wins. An observation repeating the values of the interval already running is ignored. One whose values are all null closes the running interval rather than starting one, and does nothing if none is running. The last interval of a key is left open ended.

`coalesce_history(key)` replaces intervals that meet end to end and carry the same values with the single interval they span, and never merges across a gap. `flatten_history(key)` removes overlaps by applying the rows of a key in the order they appear, each one taking the instants it covers away from the ones before it, so an interval cut through the middle survives as two rows and one that is covered completely disappears. `split_history(key, boundaries)` cuts every interval at each instant in `boundaries` falling strictly inside it. `clip_history(key, start, end=None)` keeps only the part of each interval inside that window and drops any interval sharing no instant with it; a null, empty or backwards window raises a `ValueError`.

`history_at(instant)` returns the rows covering `instant`, in their original order, without the two interval columns; a null instant raises a `ValueError`. `history_gaps(key)` and `history_overlaps(key)` return only key and interval columns: the stretches between one interval and the next, and the stretch shared by each pair of intervals of a key. `history_spans(key)` returns one row per key with its earliest start, its latest end and the time its intervals cover, in a `TimeDelta` column named by `duration_column_name`, defaulting to `duration`; the end and the duration are null when one interval is open ended. `coalesce_history`, `history_gaps`, `history_spans` and `history_events` raise a `ValueError` when a key has overlapping intervals.

`join_history(right_table, key, inner=True)` pairs the rows of two tables that share a key and cover a common instant, one row per pair over the stretch they share, so intervals that only touch produce nothing. Both tables must name their key columns and their interval columns the same way, or a `ValueError` follows, and must bound their intervals with the same data type. A key given by index is resolved in each table on its own, so tables that order their columns differently have to be joined by name. The columns are the key columns, the interval columns, this table's value columns, then the right table's value columns, with a "2" suffix on any name already taken. Rows follow this table's row order and then the right table's. With `inner=False`, each row of this table contributes its pairs first and then, in time order, whatever is left of its own interval once the shared stretches are taken away, carrying nulls in the right hand columns.

`history_events(key)` goes the other way. Each interval contributes the moment it began along with its values, and an interval ending where no other one begins also contributes the moment it ended with null values, since nothing is in effect from there. The interval columns are replaced by one column named by `effective_column_name`, defaulting to `effective`, and the rows of a key come out in order of that moment. `Coverage(start_column_name='valid_from', end_column_name='valid_to')` is an aggregation giving how much time a table's intervals cover as a `TimeDelta`, counting a stretch once however many intervals claim it, null when any interval is open ended, and zero when the table has no rows. All of these methods work on a `TableSet` too.
