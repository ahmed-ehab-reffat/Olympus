Title: Validate OME-TIFF pyramid storage

Add `TiffFile.validate_ome_pyramid(*, strict=False, assert_=True)` as a read-only structural validator for OME-TIFF pyramids. It returns `True` for a valid file. Invalid input raises `AssertionError` unless `assert_` is false, in which case it returns `False`. A non-OME TIFF is invalid, while a valid OME-TIFF without sub-resolutions is valid. Malformed or unreadable pyramid relationships must produce that validation result rather than leaking an unrelated parser exception.

Default validation covers every OME image series exposed by the file, including series whose mapped planes reside in companion TIFF files. Validation must reopen companions when necessary and restore each companion's prior open or closed state after both successful and failed validation. Every full-resolution plane mapped by the OME metadata must be present on its file's primary IFD chain. Each sub-resolution must be listed directly in tag 330 of exactly one owning full-resolution plane. The tag-330 offsets must be strictly ordered by decreasing plane area, and none may also occur on a primary IFD chain. All full-resolution planes in one image series must have the same full-resolution XY shape, the same number of sub-resolution levels, and the same XY shape at each sub-resolution level. Every child must be smaller than its full-resolution plane in both X and Y, but an individual axis does not have to decrease between consecutive child levels when their areas remain strictly ordered.

With `strict=True`, also enforce the OME recommendations. Every child must have the reduced-image bit set in `NewSubFileType`, but other bits may also be set; page axes and nonspatial dimensions must remain unchanged; and one integer downsampling factor must apply to X and Y and remain constant between consecutive levels of an image series. Different image series may use different factors. For odd dimensions, each axis at each step may independently use floor or ceiling division rather than requiring exact divisibility.

Do not decode pixel data, call `OmeXml.validate`, or reject a pyramid solely because it uses otherwise valid tile, strip, or compression settings. Storage choices are independent between full-resolution and child IFDs, so mixed tile and strip layouts are valid.
