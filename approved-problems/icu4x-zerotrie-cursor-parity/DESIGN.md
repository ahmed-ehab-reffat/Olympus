The replay establishes that the nine passing implementations are generic

patches. Further Cartesian layout fixtures are therefore forecast to remain at

while the cursor is partway through a binary span and after a current value was
taken. Its concrete representation and public type name are not prescribed;
returning a dedicated view or a cursor-backed view are both legitimate.

## Planned public contract

Add public, allocation-free cursors to `ZeroTriePerfectHash`,
`ZeroTrieExtendedCapacity`, and runtime-dispatched `ZeroTrie`. Preserve the
existing serialized format and ASCII cursor behavior. The new cursors support
one-byte stepping, destructive value extraction, emptiness, indexed probing,
independent cloning, `core::fmt::Write`, and closure-driven text lookup. They
work across every serialized layout accepted by the named trie types, including
partially consumed spans, empty/prefix keys, and extended-capacity offsets, and
across every runtime `ZeroTrie` flavor.

The API names of concrete cursor structs and their internal representation are
not part of the discriminator contract. Tests consume cursors through inferred
return types and public behavior, leaving room for a shared state machine,
variant-specific cursor types, or a sealed/generic implementation.
