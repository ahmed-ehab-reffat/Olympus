# Add simulation models for external modules and submodules

Extend the simulator so that Python code can stand in for an `Instance` of an external module, or for a submodule of the design.

`Simulator.add_instance_model(constructor, *, type=None, path=None)` attaches a model to instances, selected by type name or by one dotted path rooted at the top-level elaboratable, `top`; exactly one selector is required, otherwise `ValueError`. `Simulator.add_submodule_model(constructor, *, path)` attaches one to a submodule that is an interface object with a signature. The submodule's own logic and all logic below it are then left unevaluated. A selector matching nothing raises `NameError`. `Simulator.instances()` and `Simulator.submodules()` return `(type, path)` pairs and paths, ordered from the top of the hierarchy down, and models are started and evaluated in that same order. Replacing a submodule drops what it swallowed from both listings, keeping only the submodule itself, though naming a swallowed target still raises `DriverConflict` rather than `NameError`.

A constructor is an async function called with the simulator context and a handle; anything else raises `TypeError`. It runs once per target when the model is added, and again on reset. A handle carries `path`, and `inputs` and `outputs` mapping port names, or signature member paths joined with dots, to their connected values, a member with a shape-castable type keeping that type so a model can drive it or one of its fields; an instance handle also carries `type`, `parameters` and `attributes`, keyed without their prefixes. Ports connected to an `IOValue` are left out of a handle.

What a model drives is visible to the design and to other models in the same delta cycle, and a model waiting on its own output runs again in that same delta cycle until values settle. Models alone never keep `run()` advancing, unless a model makes itself critical, and then `run()` keeps going until it leaves that critical section. Models never alter the design itself, so converting one is unaffected. A model may sample values with `ctx.get` and wait on any input, including one connected to an expression or a constant rather than a bare signal, seeing its initial value. It may also wait for time to pass or for a clock edge; a wait still in progress is discarded by `reset()`, and an exception raised in a model propagates out of `run()`. Path selection overrides type selection for the instance it names.

What a target drives is tracked per bit, so models connected to disjoint parts of one signal coexist and each may drive only its own part. A port may also be connected to a constant, which nothing drives. `DriverConflict` is raised for driving any bit the target does not drive, for a second model on one target, for two models whose targets contain one another whichever is added first, and for a clock and a model driving the same signal. An addition that raises leaves the simulation unchanged. Once the simulation has advanced, adding a model raises `RuntimeError` until `reset()`.
