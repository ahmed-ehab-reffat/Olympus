Title: Add dependency-closed dataset subsetting

Add `kapture.algo.subset.subset_kapture(kapture_data, start_timestamp=None, end_timestamp=None, sensor_ids=None, image_ids=None)`. It must return a new, independent `Kapture` model selected by an inclusive timestamp interval, physical sensor identifiers, camera image identifiers, or their conjunction. Image identifiers are camera-record paths. When `image_ids` is supplied, first find requested camera records that also satisfy the timestamp and sensor filters. Their timestamps are the only timestamps eligible in every record family, and a surviving camera record must additionally have a requested path. Validate requested images against all source camera-record paths before applying the other filters, so a known image excluded by another selector produces an empty result rather than an unknown-image error. Apply the resulting predicate to every record family. Keep only sensor definitions used by surviving records; follow rig membership transitively through nested rigs; and keep trajectory entries only at surviving record timestamps for retained sensors or required rig ancestors.

Camera record paths define the surviving image identifiers. Intersect keypoints, descriptors, and global-feature collections with those identifiers. Keep a match only when both images survive. Keep each 3D point that has at least one surviving observation, compact retained points in source order, and remap observation point identifiers accordingly. A call without timestamp, sensor, or image filters must produce an independent full copy. Raise `ValueError` for reversed timestamp bounds and unknown physical sensor or image identifiers. Exact exception messages are not prescribed; absent collections may be represented by `None` or an empty collection.

Also add `kapture.algo.subset.subset_kapture_from_dir(source_path, output_path, start_timestamp=None, end_timestamp=None, sensor_ids=None, image_ids=None, force=False)`. It must load, subset, save, and return a self-contained dataset. Copy every retained camera, depth, lidar, feature, and match payload. Kapture supports feature collections stored either as ordinary files or in tar collections; preserve that storage mode independently for each retained collection. The saved result must reopen through the existing public readers. Raise `ValueError` for identical source and output paths. `force` may authorize replacement of existing kapture data at a distinct output path. A successful replacement must remove old kapture metadata and payload files that are not part of the new dataset, while preserving every pre-existing non-kapture file at any nesting depth unless the new dataset claims that exact path. Empty directories and other unreferenced paths may remain. Materialization must be transactional: if the operation raises for any reason, a pre-existing output tree must retain exactly the same paths and file bytes, while an output path that did not exist before the call must remain absent.

In `pyproject.toml`, the PEP 621 `[project.scripts]` table must declare `kapture_subset = "tools.kapture_subset:subset_command_line"`; the module must expose that exact `subset_command_line` callable and must also be executable as `python -m tools.kapture_subset`. The command must accept required `--input`/`-i` and `--output`/`-o` paths, optional inclusive `--start-timestamp` and `--end-timestamp` bounds, repeatable `--sensor` and `--image` filters, and `--force`.
