## Capture construction

The first section is little-endian and has a finite section length. The
generator and scanner use the draft's corrected rule that this signed length
counts bytes following the Section Header Block, excluding the SHB itself.
The second section is big-endian and uses `-1` for unspecified length.

Each section resets Interface ID 0:

| Section | ID 0 link type | Snap length | `if_tsresol` | Identity |
|---|---:|---:|---:|---|
| Little-endian | Ethernet, 1 | 65,535 | 6 | `eth-little`, Ethernet description |
| Big-endian | Linux cooked SLL, 113 | 56 | 9 | `sll-big`, SLL description |

Both IDBs also carry `if_tsoffset=7` and an unknown option. Ethernet and SLL
were chosen because the repository's libpcap-backed BPF wrapper can compile
`tcp` for both. An earlier raw-IP variant used numeric LINKTYPE_RAW 101, for
which the Linux wrapper could not compile this filter; using another supported
but distinct link type tests section-local identity without turning a libpcap
platform limitation into a hidden requirement.

The physical block sequence is intentionally interleaved:

- little-endian: SHB, IDB, kept TCP EPB, NRB, do-not-copy Custom, rejected
  UDP EPB, ISB, copyable Custom, unknown, DSB;
- big-endian: SHB, IDB, DSB, rejected UDP EPB, NRB, copyable Custom, kept TCP
  SPB, ISB, do-not-copy Custom, unknown.

The EPBs use non-default raw timestamp ticks, different captured/original
lengths, comments, flags, hash, packet ID, queue, and unknown options. The
SPB exercises its implicit section-local Interface ID 0 and the IDB snapshot
length. NRB, ISB, DSB, both Custom codes, and unknown blocks have
distinguishable section-specific bytes.

## Independent scanner and oracle

The scanner does not call PcapPlusPlus or LightPcapNg. It:

1. recognizes every SHB from its invariant type bytes and derives that
   section's byte order from the Byte-Order Magic;
2. validates each leading/trailing block length, 32-bit alignment, packet
   padding, section version, and finite section boundary;
3. resets its interface count at every SHB and checks EPB/ISB references and
   SPB's implicit local ID 0;
4. parses Ethernet and SLL only far enough to count TCP versus UDP;
5. scans the actual result before comparing it byte-for-byte with the
   independently generated expected result; and
6. asserts two sections, two TCP and zero UDP packets, two NRB/ISB/DSB/
   copyable-Custom/unknown blocks, and zero do-not-copy Custom Blocks.

Exact comparison also checks retained block order, raw timestamps, options,
payloads, and padding without sharing a production parser. The finite first
section's length field is the sole retained-block field expected to change
because dropped blocks shorten the section. The unspecified length in the
second SHB remains `-1`.

The fixture is adequate to demonstrate the semantic families, but it does not
make those blocks independent implementation decisions: a correct raw-copy
default branch preserves NRB, DSB, copyable Custom, unknown blocks, and their
options together. That convergence was the central L1 difficulty signal.

## L2 focused fixtures

The final harness generates three additional deterministic captures directly
in `PcapNgCopyTest.cpp`; no external fixture file is required.

`InterfaceSelection` contains two sections with two differently typed IDBs
each. In the little-endian section, ID 0 is Linux cooked SLL and ID 1 is
Ethernet; in the big-endian section those meanings are reversed. Each section
contains TCP and UDP EPBs referencing ID 1, plus an ISB referencing ID 1. The
expected output retains all four IDBs in physical order and only the TCP EPBs.
This makes an index-zero filter choose the wrong result in one section and
proves that numeric IDs are section-local.

`OptionPreservation` places valid Custom Options in retained IDB and EPB option
areas. It uses copyable code 2989 and do-not-copy code 19373, each with a
four-byte PEN followed by distinguishing data. The complete output is compared
byte-for-byte, so neither option may be stripped or normalized. The same
capture includes retained Name Resolution and Decryption Secrets Blocks to
exercise their valid inner framing.

`MalformedOptions` starts from valid IDB, EPB, NRB, and DSB blocks, then
independently changes an option or record length so its padded field overruns
the owning block area. Each case must return `false` and leave a pre-existing
sentinel destination unchanged. The cases share one structural invariant but
cover the distinct public field starts used by the retained standardized block
families.

## L3 focused fixtures

`OptionTermination` builds little- and big-endian sections whose retained
SHB, IDB, EPB, ISB, NRB, and DSB option lists contain a valid padded field but
no explicit `opt_endofopt`. Each list ends exactly at the owning block
boundary. The accepted output is compared byte-for-byte. This is a valid-reader
boundary independent of malformed-option rejection.

`FilterState` configures a non-TCP expression and supplies distinguishable
TCP and UDP EPBs plus SPBs. The expected packet choices prove that both packet
families use the reader's current filter rather than an empty or hard-coded
`tcp` predicate.

Historical L3 `MalformedFraming` included an SHB minor version other than 0;
that assertion is retired in L5 as an unfair exact-minor policy.
`MalformedOptions` adds independent overrun fields at SHB and ISB option
starts and in the NRB option area after a valid record terminator.
`MalformedReferences` adds both truncated and extra-payload SPBs whose total
length disagrees with the captured size implied by IDB 0. Every rejection
preserves the pre-existing destination sentinel.

## L4 focused fixtures

`DefaultAndClearedFilter` reuses the valid mixed TCP/UDP filter-state capture,
which contains both EPBs and SPBs. It first calls `copyFiltered()` on a fresh
reader and then after setting and clearing a filter. Both outputs must equal
the complete input byte-for-byte, proving the repository's established empty
filter semantics for both packet block families.

`ReservedFieldOpacity` creates a valid little-endian section whose IDB reserved
field contains `0xa55a`. A TCP EPB and SPB use that interface. The copy must
succeed and equal the input exactly: readers ignore the reserved field, while
byte preservation forbids normalizing it.

`LocalUseOpacity` places block type `0x80000001` between a valid IDB and TCP
EPB. Its eight-byte opaque body deliberately resembles an impossible option
header if interpreted at the wrong offset. The block is nevertheless valid by
outer framing and must survive byte-for-byte. This distinguishes opaque block
handling without inventing a private payload grammar.

## L5 fairness correction

`MalformedFraming` continues to reject an unsupported major version, bad
byte-order magic, outer truncation, unequal trailing block length, and invalid
finite section boundaries. It no longer treats minor version 1 as malformed,
and the independent output scanner checks only major version 1.

No replacement minor-version fixture is added. An audit-only variant changes
the `ReservedFieldOpacity` capture's SHB from 1.0 to 1.1 and confirms that the
reference accepts and exact-copies it. This establishes the corrected
reference behavior without turning version permutations into another hidden
discriminator.

## L6 focused fixtures

`InPlaceReplacement` reuses `makeFilterStateCapture(false)`, which contains
valid TCP and UDP EPBs and SPBs but no DSB. The reader selects UDP and writes
back to the exact input path. The expected bytes are
`makeFilterStateCapture(true)`. This isolates input/output alias publication
from the DSB-options defects already observed in three L5 runs.

`DiscardedPacketOptions` creates one little-endian section with an Ethernet
IDB, a UDP EPB, and a valid TCP EPB. The UDP EPB has valid outer framing,
trailing length, section-local Interface ID, captured/original lengths, and
packet-data bounds. Its first option length is changed to `0xfffc`, making only
the discarded option area invalid. With the current `tcp` filter, the expected
file omits the UDP EPB and retains the TCP EPB byte-for-byte. This distinguishes
validation required for retained standardized blocks from safety checks needed
before filtering.

`StructureAndFiltering` retains its original bytes and assertions but invokes
the operation through a const reference after configuring the mutable reader.
This is a compile-time API fixture and does not constrain parser architecture.
