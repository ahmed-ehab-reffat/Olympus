# Add frame level operations to enhanced multi-frame instances

Add a `pydicom.multiframe` module, the same objects also reachable from `pydicom`, holding `frame_attributes(ds, index)`, `varying_attributes(ds)`, `extract_frames(ds, indices)`, `merge_frames(datasets)`, `group_frames(ds, keys)`, `sort_frames(ds, keys)` and `MultiFrameError`. All six reject the same malformed instances. `MultiFrameError`, a `ValueError`, is raised for a dataset with no per-frame groups, empty counting as none, transfer syntax, SOP class or instance UID, not exactly one pixel data element, a shared group sequence present but not holding one item, a frame count absent or disagreeing, pixel data too short or malformed, a missing frame, an empty or repeating selection, no keys, a key that is not an attribute name or tag, incomparable values, and uncombinable inputs.

`frame_attributes` flattens the macros applying to one zero-based frame into the attributes inside them, not the macro sequences, shared first, the frame's own second, a per-frame macro replacing the shared macro carrying its tag. It is a copy; the instance is unaffected. `varying_attributes` returns the tags whose effective value is not the same for every frame, nothing for one frame.

`extract_frames` keeps the frames `indices` names, in order. `merge_frames` takes every frame of its inputs, one or more, which must agree on SOP class, transfer syntax, pixel data element and image pixel attributes. `group_frames` returns a list of one instance per distinct combination of the effective values of `keys`, in first-appearance order, keeping their old order, frames carrying none grouping together, even when that is every frame. `sort_frames` puts them in ascending order of those values, first key first, missing values last, ties as they were. Multi-valued attributes order value by value.

A derived instance carries one shared group. In-stack positions are renumbered from one within each stack, in frame order, among those carrying them. Among the frames carrying index values, described or not, a dimension every one of them reaches with one value is then dropped, from the dimension index description and from those frames; one they do not all reach is kept. A frame's values element goes when it empties, its macro stays; the description goes when nothing is left in it. A dimension whose `DimensionIndexPointer` names an attribute takes its values from that attribute instead, a frame without it not reaching that dimension. What remains is renumbered, each alone, to 1, 2, 3 in first-seen order. Only then is a macro with the same value for every frame stored once, in the shared group, every other in each frame's own. A macro may hold several items, and sameness is the whole macro, items and all. Its pixel data element is rebuilt in the new frame order, one-bit data packed and measured in bits, not bytes, encapsulated again if it was, its length left undefined, padded to an even length if not, any extended offset table dropped. It takes a new SOP instance UID, its file meta naming that and its SOP class, and a source image sequence holding one item per input, in input order, naming its SOP class, instance UID and the 1-based frame numbers taken from it, in result order. Everything else comes from the first input, copied. Inputs are unchanged and share nothing with the result.
