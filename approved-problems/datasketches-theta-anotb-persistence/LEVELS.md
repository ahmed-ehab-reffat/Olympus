# Calibration levels — stateful Theta A-not-B persistence

## Level 1 — clarified prompt revision (superseded before calibration)

The initial immutable submission package adds the complete public persistence
lifecycle in one revision. It has 16 solution-required focused TestNG methods,
17/17 killed compile-valid mutants, 102 selected pre-existing regression tests,
and a 2,295-test complete composed reference suite.

There are no exact historical solver patches. The pre-authoring forecast is
3–6 successful solvers out of ten, with the upper edge carrying too-easy risk.
That is a fresh-calibration expectation derived from persistence trajectory
patterns and the four-production-class, roughly 230-line cheapest complete
prototype; it is not a compatibility replay estimate.

Fresh Level 1 calibration ended at 0/10 because no solver run was started before
the platform-path environment defect required an artifact revision.

The first Level 1 artifact set was never calibrated. Auto-review found that two
already-tested contracts were missing from its public prose. That prompt-only
revision names `ThetaSetOperation.getMaxAnotBResultBytes(int)` and the direct
`setA(null)` reset-before-error ordering. Its prompt hash is
`959c446e9974b757fe3a105e03d3cfdaec61950c48ef8407f520ca754caf98c0`;
all exact gates were rerun, and its calibration remained 0/10.

## Level 2 — platform-path repair (quarantined batch)

The platform's derived runtime discarded the Dockerfile's custom `/opt` PATH,
so Level 1's harness stopped at bare `mvn` before any test. Level 2 changes only
environment discovery: `test.sh` explicitly selects `/opt/java`,
`/opt/maven/bin/mvn`, the submitted toolchain, and the offline cache; the
Dockerfile exposes Maven, Java, and javac through `/usr/local/bin` links.

The public prompt, production reference, hidden Java test source, 16 focused
method identities, and 17-mutant discriminator set are unchanged. Fresh Phase
A, exact Phase B, a platform-like stripped-environment replay, the 2,295-test
reference suite, and all downstream audits pass. The prior 3–6/10 forecast is
therefore unchanged and remains a fresh-calibration expectation, not a
compatibility replay estimate.

Five Nova attempts were later supplied for this version. One was a genuine
15/16 short-header near miss and four implemented all 16 focused behaviors, but
the evaluator protected and restored the obsolete
`SetOperationTest.checkBuilderAnotB_noSeg` predicate. Three correct behavioral
patches were consequently labeled test-broken, and merge-reset/hybrid trees
appeared in the batch. Per the environment protocol, the entire batch is
quarantined and contributes 0 valid calibration runs. Its raw trajectories and
production patches remain design and compatibility evidence only.

## Level 3 — accepted final package

Level 3 keeps the clarified public prompt and Dockerfile, makes `test.patch`
strictly additive, removes `SetOperationTest` from the selected base lane, and
puts the clean obsolete-regression replacement in the reference-only
`solution.patch`. It also expands malformed-state coverage to independently
exercise nonpositive theta and invalid/duplicate retained hashes. The hidden
suite retains the same 16 solution-required method identities.

Before the artifact changes, the five Level 2 patches predicted four compatible
passes and one existing near miss: 4/5. The corresponding fresh-calibration
expectation was 7–9/10. This was explicitly a compatibility replay forecast,
not a claim of successful difficulty hardening.

The final exact replay observes 4/5, matching the forecast. All four compatible
patches pass 82/82 base and 16/16 focused; the fifth is 14/16, missing generic
short-header normalization and duplicate-hash validation. Pristine/reference complete suites pass 2,279/2,279
and 2,295/2,295, and the final mutation audit kills 19/19 mutants.

Level 3 is environment-valid and fair. Its 80% compatible success was outside
the intended difficulty band and fresh calibration remained 0/10, but the user
confirmed platform acceptance on 2026-08-17. That external disposition closes
the immutable package; no Level 4 revision or additional solver batch is
planned.
